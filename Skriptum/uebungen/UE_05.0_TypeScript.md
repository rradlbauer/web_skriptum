# Übungen zu 05.0 – TypeScript Grundlagen

## UE_05.0_1 – Interfaces und Funktionen erstellen

**Aufgabe**: Erstelle eine neue TypeScript-Datei `exercises.ts` mit Interfaces und Funktionen für Patienten und Ärzte.

### Schritte

1. **Definiere folgende Interfaces:**

```typescript
interface Patient {
    id: number;
    firstName: string;
    lastName: string;
    email: string;
    dateOfBirth: string;
}

interface Doctor {
    id: number;
    firstName: string;
    lastName: string;
    specialization: string;
    medicalLicenseNumber: string;
    active: boolean;
}
```

2. **Schreibe Funktionen:**

```typescript
// Erstellt einen Patienten und gibt ihn zurück
function createPatient(id: number, firstName: string, lastName: string, email: string, dob: string): Patient {
    // Dein Code hier
}

// Erstellt einen Arzt
function createDoctor(id: number, firstName: string, lastName: string, specialization: string, license: string): Doctor {
    // Dein Code hier
}

// Gibt die info eines Patienten als String zurück
function formatPatient(p: Patient): string {
    // Rückgabe: "Anna Schmidt (anna@email.at, geb. 1990-05-15)"
}

// Gibt die info eines Arztes als String zurück
function formatDoctor(d: Doctor): string {
    // Rückgabe: "Dr. Thomas Tandler | Kardiologie | L-12345 | Aktiv"
}
```

3. **Teste deine Funktionen:**

```typescript
const patient = createPatient(1, "Anna", "Schmidt", "anna@email.at", "1990-05-15");
console.log(formatPatient(patient));

const doctor = createDoctor(1, "Thomas", "Tandler", "General Practice", "L-12345");
console.log(formatDoctor(doctor));
```

**Kontrollfragen**:
1. Was passiert, wenn du bei `createPatient()` einen Number-Wert als `firstName` übergibst?
2. Was würde passieren, wenn du das `active`-Feld bei `createDoctor()` vergisst?
3. Warum ist der Rückgabewert von `createPatient()` explizit als `Patient` annotiert, wenn TypeScript den Typ auch automatisch ableiten könnte?

## UE_05.0_2 – Filterfunktion mit Typisierung

**Aufgabe**: Schreibe eine Funktion, die eine Liste von Health Records nach Kategorie filtert.

### Schritte

1. **Definiere ein HealthRecord-Interface:**

```typescript
interface HealthRecord {
    id: number;
    title: string;
    category: "ILLNESS" | "VACCINATION" | "MEDICATION" | "OTHER";
    description: string;
    dateFrom: string;
    severity?: string; // optionales Feld
}
```

2. **Schreibe die Filterfunktion:**

```typescript
function filterByCategory(records: HealthRecord[], category: string): HealthRecord[] {
    // Dein Code hier: gib nur Records zurück, deren category übereinstimmt
}
```

3. **Teste mit Beispieldaten:**

```typescript
const records: HealthRecord[] = [
    { id: 1, title: "Erkältung", category: "ILLNESS", description: "Schnupfen", dateFrom: "2025-06-01", severity: "Mild" },
    { id: 2, title: "COVID-19 Booster", category: "VACCINATION", description: "Comirnaty", dateFrom: "2025-03-15" },
    { id: 3, title: "Ibuprofen", category: "MEDICATION", description: "400mg", dateFrom: "2025-01-01" },
    { id: 4, title: "Rückenschmerzen", category: "ILLNESS", description: "Unterer Rücken", dateFrom: "2025-04-20", severity: "Moderate" },
];

console.log(filterByCategory(records, "ILLNESS"));      // 2 Treffer
console.log(filterByCategory(records, "VACCINATION"));  // 1 Treffer
console.log(filterByCategory(records, "SURGERY"));      // 0 Treffer
```

**Bonus**: Erweitere die Funktion um einen **Optional-Chaining**-Aufruf, der auch nach `severity` filtern kann:

```typescript
function filterByCategoryAndSeverity(
    records: HealthRecord[],
    category: string,
    severity?: string
): HealthRecord[] {
    // Nur filtern, wenn severity angegeben wurde
}
```

**Kontrollfragen**:
1. Was bedeutet das `?` bei `severity?: string`?
2. Warum ist `category: "ILLNESS" | "VACCINATION" | "MEDICATION" | "OTHER"` besser als `category: string`?
3. Was passiert in deiner Funktion, wenn `filterByCategory(records, "ILLNESS")` aufgerufen wird, aber `records` leer ist?

## UE_05.0_3 – TypeScript kompilieren und Ergebnis untersuchen

**Aufgabe**: Kompiliere deine TypeScript-Datei und vergleiche das Ergebnis mit dem Original.

### Schritte

1. **Erstelle die Datei** `frontend/ts/exercises.ts` mit deinem Code aus UE_05.0_1 oder UE_05.0_2.

2. **Kompiliere sie:**

```bash
cd frontend
npx tsc
```

3. **Untersuche das Ergebnis** in `backend/src/main/resources/static/js/exercises.js`:

```bash
# Was ist passiert?
# - Interface-Definitionen wurden ENTFERNT (existieren nicht in JavaScript)
# - Typ-Annotationen wurden ENTFERNT
# - Der Code ist jetzt normales JavaScript
```

4. **Vergleiche typische Transformationen:**

| TypeScript | Kompiliertes JavaScript |
|-----------|------------------------|
| `const name: string = "Anna"` | `const name = "Anna"` |
| `function add(a: number, b: number): number` | `function add(a, b)` |
| `interface Patient { ... }` | *(ganz entfernt)* |
| `enum Category { Illness = "ILLNESS" }` | `var Category; (function(c){...})(Category \|\| {})` |

**Reflexionsfragen**:
1. Welche TypeScript-Features überleben die Kompilierung nicht?
2. Warum ist das sinnvoll?
3. Kann ein Entwickler, der nur JavaScript kennt, den kompilierten Code verstehen?
