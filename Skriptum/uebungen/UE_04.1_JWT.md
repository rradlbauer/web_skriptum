# Übung 04.1 - JWT (JSON Web Token)

## Übung 04.1_1: JWT bei jwt.io decodieren

**Aufgabe:**

1. Starte die Anwendung und logge dich ein (z.B. über das Frontend oder mit `curl`):
```bash
curl -X POST http://localhost:8080/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"admin@clinicaldiary.at","password":"admin"}'
```

2. Kopiere den Wert des `"token"`-Felds aus der Antwort.

3. Gehe zu [jwt.io](https://jwt.io) und füge den Token in das **Encoded**-Feld ein.

4. Identifiziere die drei Teile:
   - **Header**: Welcher Algorithmus (`alg`) wird verwendet?
   - **Payload**: Welche Claims sind enthalten? (sub, userId, role, iat, exp)
   - **Signature**: Kannst du den Signatur-Algorithmus erkennen?

5. **Frage:** Ist der `exp`-Wert (Ablaufzeitpunkt) in der Zukunft? Berechne, wann der Token abläuft.

## Übung 04.1_2: Ablaufzeit ändern

**Aufgabe:**

1. Ändere in `application.properties` den Wert von `app.jwt.expiration-ms`:
```properties
# Nur 10 Sekunden gültig (statt 24 Stunden):
app.jwt.expiration-ms=10000
```

2. Starte die Anwendung neu.

3. Logge dich ein und kopiere den Token.

4. **Warte 10 Sekunden** und versuche dann, einen geschützten Endpoint aufzurufen:
```bash
curl http://localhost:8080/api/patient/1 \
  -H "Authorization: Bearer <dein-token>"
```

5. **Frage:** Welche Fehlermeldung erhältst du? Erkläre, warum der Token abgelehnt wird.

6. **Setze den Wert wieder auf** `86400000` (24 Stunden) zurück!

## Übung 04.1_3: Neuen Claim hinzufügen

**Aufgabe:**

1. Erweitere die `generateToken()`-Methode in `JwtTokenProvider.java` um einen neuen Claim `"department"`:

```java
public String generateToken(Long userId, String email, String role, String department) {
    Date now = new Date();
    Date expiryDate = new Date(now.getTime() + expirationMs);

    return Jwts.builder()
            .subject(email)
            .claim("userId", userId)
            .claim("role", role)
            .claim("department", department)    // NEU
            .issuedAt(now)
            .expiration(expiryDate)
            .signWith(key)
            .compact();
}
```

2. Erstelle eine neue Methode zum Auslesen:
```java
public String getDepartmentFromToken(String token) {
    return Jwts.parser()
            .verifyWith(key).build()
            .parseSignedClaims(token)
            .getPayload()
            .get("department", String.class);
}
```

3. Passe den Login-Endpoint in `AuthController.java` an:
```java
String token = jwtTokenProvider.generateToken(
    patient.getId(), patient.getEmail(), "PATIENT", "Kardiologie");
```

4. **Teste:** Logge dich ein und dekodiere den Token bei jwt.io. Erscheint der neue Claim `"department": "Kardiologie"` im Payload?

5. **Frage:** Warum ist es wichtig, dass der `getDepartmentFromToken()`-Aufruf einen `null`-Fallback hat, falls der Claim nicht existiert?
