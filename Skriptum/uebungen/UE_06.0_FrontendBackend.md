## UE_06.0_1 – Neues API-Endpoint und Frontend-View

**Aufgabe**: Erstelle ein neues Backend-Endpoint und ein Frontend-View, das die Daten anzeigt.

### Hintergrund

Das Clinical Diary-Backend hat bereits ein `/api/superuser/stats`-Endpoint, das Statistiken liefert. Stelle dir vor, du möchtest ein neues Endpoint `/api/patients/me/summary` erstellen, das eine Zusammenfassung der Patienten-Daten liefert.

### Schritte

1. **Analysiere** die bestehende `api()`-Funktion in `frontend/ts/app.ts` (Zeile ~42–56). Verstehe, wie HTTP-Anfragen gesendet und Antworten verarbeitet werden.

2. **Erstelle ein neues Backend-Endpoint** (im Java-Teil):
   - Erstelle eine neue Methode in einem Controller, die `/api/patients/me/summary` bedient
   - Rückgabe als JSON: `{ totalRecords: number, lastRecordDate: string, categories: string[] }`

3. **Erstelle ein neues Frontend-View** in `app.ts`:

```typescript
async function renderPatientSummary() {
    const content = document.getElementById("tab-content")!;
    try {
        const summary = await api("GET", "/api/patients/me/summary");
        content.innerHTML = `
            <h2>Meine Zusammenfassung</h2>
            <div class="stats-grid">
                <div class="stat-card">
                    <div class="stat-value">${summary.totalRecords}</div>
                    <div class="stat-label">Gesamte Einträge</div>
                </div>
                <div class="stat-card">
                    <div class="stat-value">${summary.lastRecordDate || 'Keine'}</div>
                    <div class="stat-label">Letzter Eintrag</div>
                </div>
            </div>
            <h3>Kategorien</h3>
            <p>${summary.categories.join(', ')}</p>`;
    } catch (e: any) {
        content.innerHTML = `<div class="alert alert-error">${e.message}</div>`;
    }
}
```

4. **Füge den Tab** in `navigatePatient()` hinzu (ähnlich wie in UE_05.1_3).

**Kontrollfragen**:
1. Was passiert, wenn das Endpoint einen 401-Fehler zurückgibt (kein gültiger Token)?
2. Warum verwendet die `api()`-Funktion `response.json()` und nicht `response.text()`?
3. Wie würdest du vorgehen, wenn das Endpoint einen anderen Content-Type als JSON zurückgibt?


3. **Beim Rendern die gemerkte E-Mail wiederherstellen:**

```typescript
function renderLogin() {
```

## UE_06.0_3 – Modal-Dialog zum Bearbeiten eines Health Records

**Aufgabe**: Analysiere den bestehenden `showRecordModal()` in `app.ts` (Zeile ~353–496) und erweitere ihn um ein Bestätigungsdialog.

### Schritte

1. **Lies den Code** von `showRecordModal()` und verstehe:
   - Wie das Modal dynamisch erstellt wird (`document.createElement`)
   - Wie Formularfelder befüllt werden (bei Edit vs. bei Neu)
   - Wie die Kategorie-abhängigen Felder ein-/ausgeblendet werden
   - Wie der Speichern-Button funktioniert

2. **Füge eine Bestätigung** vor dem Löschen hinzu (im `deleteRecord`-Handler):

```typescript
(window as any).deleteRecord = async function(recordId: number) {
    // Ersetze das einfache confirm() durch ein benutzerdefiniertes Modal:
    const modal = document.createElement("div");
    modal.className = "modal-overlay";
    modal.innerHTML = `
        <div class="modal" style="max-width:400px">
            <h2>Sicher löschen?</h2>
            <p>Dieser Health Record kann nicht wiederhergestellt werden.</p>
            <div class="modal-actions">
                <button class="btn btn-outline" id="confirm-cancel">Abbrechen</button>
                <button class="btn btn-danger" id="confirm-delete">Löschen</button>
            </div>
        </div>`;
    document.body.appendChild(modal);

    modal.querySelector("#confirm-cancel")!.addEventListener("click", () => modal.remove());
    modal.querySelector("#confirm-delete")!.addEventListener("click", async () => {
        try {
            await api("DELETE", `/api/patients/me/records/${recordId}`);
            modal.remove();
            renderPatientRecords();
        } catch (e: any) {
            alert(e.message);
        }
    });
};
```

3. **Teste** das neue Modal, indem du einen Record löschst.

**Bonus**: Füge dem Modal eine Animation hinzu (z.B. Fade-In mit CSS Transition).

**Reflexionsfragen**:
1. Was sind die Vorteile eines benutzerdefinierten Modals gegenüber `window.confirm()`?
2. Warum wird `modal.remove()` an mehreren Stellen aufgerufen?
3. Wie könnte man das Modal wiederverwendbar machen (z.B. als allgemeine Bestätigungs-Dialog-Funktion)?
