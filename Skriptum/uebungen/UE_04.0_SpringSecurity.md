# Übung 04.0 - Spring Security

## Übung 04.0_1: Öffentliche Endpoints erweitern

**Aufgabe:** Füge in der `SecurityConfig.java` eine neue `requestMatchers`-Zeile hinzu, die alle Endpoints unter `/api/superuser/**` ebenfalls als öffentlich (`permitAll()`) markiert.

```java
// Füge diese Zeile vor .anyRequest().authenticated() ein:
.requestMatchers("/api/superuser/**").permitAll()
```

**Teste:** Starte die Anwendung und rufe einen Endpoint unter `/api/superuser/` auf – z.B. mit:
```bash
curl http://localhost:8080/api/superuser/test
```

**Frage:** Was passiert, wenn du einen solchen Endpoint öffentlich machst, der eigentlich geschützt sein sollte? Warum ist das ein Sicherheitsrisiko?

## Übung 04.0_2: Neuen öffentlichen Endpoint anlegen

**Aufgabe:** Erstelle einen neuen Controller mit einem öffentlichen Endpoint:

1. Erstelle eine neue Klasse `HealthController.java` im `controller`-Paket:

```java
@RestController
public class HealthController {

    @GetMapping("/api/health")
    public ResponseEntity<?> healthCheck() {
        return ResponseEntity.ok(Map.of("status", "OK"));
    }
}
```

2. Füge in `SecurityConfig.java` einen Eintrag hinzu, damit `/api/health` ohne Authentication erreichbar ist.

**Teste:** Rufe `http://localhost:8080/api/health` im Browser oder mit `curl` auf – ohne Authorization-Header sollte die Antwort kommen.

**Frage:** Welche Endpoints in deiner Anwendung sollten öffentlich sein und welche nicht? Begründe deine Entscheidung.

## Übung 04.0_3: CSRF und Sessions erklären

**Aufgabe:** Erkläre in eigenen Worten (3–5 Sätze pro Thema):

1. **Warum ist CSRF bei JWT deaktiviert?** Was wäre anders, wenn wir Cookies statt JWT verwenden würden?

2. **Warum sind Sessions stateless?** Was sind die Vorteile und Nachteile gegenüber session-basierten Ansätzen?

3. **Was würde passieren**, wenn wir `.csrf().disable()` vergessen würden und trotzdem JWT verwenden?

**Tipp:** Recherchiere die Begriffe "CSRF-Token" und "Same-Origin-Policy", um die Zusammenhänge besser zu verstehen.
