# UE_07.4 TypeScript – fetch-API & REST – Übungen

[<<](../skriptum/07.4_Fetch_REST.md)

### UE_07.4_1: fetch-Grundlagen

1. Erkläre in eigenen Worten, was `fetch` tut und was eine Promise in diesem Zusammenhang bedeutet.
2. Schreibe eine `async`-Funktion `fetchPatients(): Promise<Patient[]>`, die `GET /api/patients` aufruft und typisiert zurückgibt (Interface `Patient`).
3. Erkläre, warum `await` nur in einer `async`-Funktion verwendet werden darf.

### UE_07.4_2: Tabelle mit API-Daten

1. Erstelle eine HTML-Tabelle mit Kopfzeile (`Name`, `Diagnose`).
2. Befülle sie mit den Daten der API – kombiniere `fetch` (Kapitel 07.4) mit den DOM-Techniken aus Kapitel 07.2.
3. Teste die Funktion (sie wird in Kapitel 09.0 gegen eine echte Spring-Boot-API laufen).

### UE_07.4_3: POST – neuen Patienten senden

1. Schreibe eine Funktion `createPatient(patient: Patient): Promise<void>`, die per `POST` das Objekt als JSON an `/api/patients` sendet.
2. Gib bei Erfolg und bei Fehler eine passende Meldung aus.
3. Erkläre die drei Bestandteile: `method`, `headers`, `body`.

### UE_07.4_4: PUT und DELETE

1. Schreibe `updatePatient(patient: Patient): Promise<void>` (PUT) und `deletePatient(id: number): Promise<void>` (DELETE).
2. Erkläre, warum die id bei `PUT`/`DELETE` in der URL steht.
3. Erkläre den Unterschied zwischen `GET` und `POST` im Hinblick auf den `body`.

### UE_07.4_5: Fehlerbehandlung

1. Ergänze `fetchPatients()` um eine `!response.ok`-Prüfung (mit `throw new Error(...)"`).
2. Probiere das Verhalten aus, indem du eine falsche URL verwendest.
3. Erkläre den Unterschied zwischen einem Serverfehler (z. B. Status `404`) und einem Netzwerkfehler.
4. Warum ist das Interface `Patient` für das Typisieren der API-Antwort wichtig?
