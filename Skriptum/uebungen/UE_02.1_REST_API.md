# Übungen zu 02.1 – REST API mit Spring Boot

## UE_02.1_1 – Einfachen REST-Controller erstellen

**Aufgabe**: Erstelle einen neuen Controller `HelloController` mit einem GET-Endpoint, der eine Willkommensnachricht zurückgibt.

### Anforderungen

1. Erstelle eine neue Datei `HelloController.java` im Package `com.clinicaldiary.controller`
2. Der Endpoint soll `GET /api/hello` lauten
3. Er soll folgendes JSON zurückgeben:
   ```json
   {
       "message": "Willkommen beim Clinical Diary!",
       "version": "1.0.0"
   }
   ```

### Vorgehensweise

- Verwende `@RestController` und `@RequestMapping`
- Verwende `@GetMapping` für den Endpoint
- Verwende `Map.of()` oder eine eigene Klasse für die Antwort
- Teste den Endpoint mit dem Browser unter `http://localhost:8080/api/hello`

## UE_02.1_2 – POST-Endpoint mit JSON-Body

**Aufgabe**: Erweitere den `HelloController` um einen POST-Endpoint, der ein JSON-Body entgegennimmt und mit zusätzlichen Feldern zurückgibt.

### Anforderungen

1. Endpoint: `POST /api/hello/greet`
2. Erwarteter Input (JSON-Body):
   ```json
   {
       "name": "Max Mustermann"
   }
   ```
3. Erwarteter Output:
   ```json
   {
       "greeting": "Hallo, Max Mustermann!",
       "timestamp": "2025-07-01T14:30:00",
       "processed": true
   }
   ```

### Hinweise

- Verwende `@RequestBody Map<String, String>` für den Input
- Verwende `LocalDateTime.now().toString()` für den Zeitstempel
- Teste mit curl:
  ```bash
  curl -X POST http://localhost:8080/api/hello/greet \
    -H "Content-Type: application/json" \
    -d '{"name": "Max Mustermann"}'
  ```

## UE_02.1_3 – Bestehenden Login-Endpoint testen

**Aufgabe**: Teste den Login-Endpoint `/api/auth/login` mit verschiedenen Tools.

### Schritte

1. **Starte die Anwendung**:
   ```bash
   cd backend
   mvnw spring-boot:run
   ```

2. **Teste den Login mit curl**:
   ```bash
   # Patient einloggen
   curl -X POST http://localhost:8080/api/auth/login \
     -H "Content-Type: application/json" \
     -d '{"email": "anna.schmidt@email.at", "password": "password123"}'

   # Arzt einloggen
   curl -X POST http://localhost:8080/api/auth/login \
     -H "Content-Type: application/json" \
     -d '{"email": "dr.tandler@klinik.at", "password": "doctor123"}'
   ```

3. **Teste einen fehlgeschlagenen Login**:
   ```bash
   curl -X POST http://localhost:8080/api/auth/login \
     -H "Content-Type: application/json" \
     -d '{"email": "falsch@email.at", "password": "falsch"}'
   ```

4. **Verwende den Token** für einen geschützten Endpoint:
   ```bash
   # Token aus der Login-Antwort kopieren und hier einfügen
   curl http://localhost:8080/api/patients/me \
     -H "Authorization: Bearer HIER_TOKEN_EINFUEGEN"
   ```

### Reflexionsfragen
- Welchen HTTP-Statuscode erhältst du bei einem fehlgeschlagenen Login?
- Was passiert, wenn du einen ungültigen Token verwendest?
- Welche Daten stehen im Token?

## UE_02.1_4 – Eigenen Endpoint: Patientenprofil

**Aufgabe**: Erstelle einen neuen Endpoint `GET /api/patients/me` im `PatientController`, der das Profil des eingeloggten Patienten zurückgibt.

### Anforderungen

1. Der Endpoint soll ein JWT-Token im `Authorization`-Header erwarten
2. Er soll folgende Daten des eingeloggten Patienten zurückgeben:
   ```json
   {
       "id": 1,
       "email": "anna.schmidt@email.at",
       "firstName": "Anna",
       "lastName": "Schmidt",
       "dateOfBirth": "1990-05-15"
   }
   ```
3. Bei fehlendem oder ungültigem Token soll ein 401-Fehler zurückgegeben werden

### Vorgehensweise

- Schaue dir den bestehenden `getProfile()`-Endpoint im `PatientController` an
- Verwende `Authentication auth`, um den eingeloggten Benutzer zu ermitteln
- Verwende `getCurrentPatientId(auth)`, um die Patienten-ID zu erhalten

### Test mit curl
```bash
# 1. Einloggen und Token kopieren
TOKEN=$(curl -s -X POST http://localhost:8080/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email": "anna.schmidt@email.at", "password": "password123"}' \
  | grep -o '"token":"[^"]*"' | cut -d'"' -f4)

# 2. Profil abrufen
curl http://localhost:8080/api/patients/me \
  -H "Authorization: Bearer $TOKEN"
```
