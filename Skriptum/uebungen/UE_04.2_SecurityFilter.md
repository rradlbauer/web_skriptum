# Übung 04.2 - Security Filter: JwtAuthenticationFilter

## Übung 04.2_1: Logging im Filter hinzufügen

**Aufgabe:** Erweitere den `JwtAuthenticationFilter` um `System.out.println`-Aufrufe, um zu sehen, was bei jedem Request passiert:

```java
@Override
protected void doFilterInternal(HttpServletRequest request,
                                HttpServletResponse response,
                                FilterChain filterChain)
                                throws ServletException, IOException {

    String header = request.getHeader("Authorization");

    if (header != null && header.startsWith("Bearer ")) {
        String token = header.substring(7);

        if (tokenProvider.validateToken(token)) {
            String email = tokenProvider.getEmailFromToken(token);
            Long userId = tokenProvider.getUserIdFromToken(token);
            String role = tokenProvider.getRoleFromToken(token);

            // NEU: Logging
            System.out.println("[JWT Filter] Authenticated user: " + email
                + " (ID: " + userId + ", Role: " + role + ")");

            var authority = new SimpleGrantedAuthority("ROLE_" + role);
            var authentication = new UsernamePasswordAuthenticationToken(
                    new UserPrincipal(userId, email, role),
                    null,
                    List.of(authority)
            );
            SecurityContextHolder.getContext().setAuthentication(authentication);
        } else {
            // NEU: Logging für ungültige Tokens
            System.out.println("[JWT Filter] Invalid token rejected");
        }
    } else {
        // NEU: Logging für Requests ohne Token
        System.out.println("[JWT Filter] No Bearer token found for: "
            + request.getMethod() + " " + request.getRequestURI());
    }

    filterChain.doFilter(request, response);
}
```

**Teste:** Starte die Anwendung und sende verschiedene Requests:
1. Ein Request **ohne** Token → Was wird geloggt?
2. Ein Request mit einem **ungültigen** Token → Was wird geloggt?
3. Ein Request mit einem **gültigen** Token → Was wird geloggt?

**Bonus:** Ersetze `System.out.println` durch einen professionellen Logger:
```java
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;

private static final Logger log = LoggerFactory.getLogger(JwtAuthenticationFilter.class);
```

## Übung 04.2_3: Rollenbasierte Endpoint-Logik

**Aufgabe:** Erstelle einen neuen Endpoint, der basierend auf der Rolle des Users unterschiedliche Daten zurückgibt:

```java
@RestController
@RequestMapping("/api/role-demo")
public class RoleDemoController {

    @GetMapping("/greeting")
    public ResponseEntity<?> greeting(Authentication auth) {
        UserPrincipal user = (UserPrincipal) auth.getPrincipal();

        String message;
        switch (user.getRole()) {
            case "PATIENT":
                message = "Willkommen, Patient! Du kannst hier deine Tagebucheinträge sehen.";
                break;
            case "DOCTOR":
                message = "Willkommen, Dr. " + user.getEmail()
                    + "! Du hast Zugriff auf deine Patienten.";
                break;
            case "SUPERUSER":
                message = "Willkommen, Administrator! Du hast vollen Zugriff.";
                break;
            default:
                message = "Unbekannte Rolle.";
        }

        return ResponseEntity.ok(Map.of(
            "email", user.getEmail(),
            "role", user.getRole(),
            "message", message
        ));
    }
}
```

**Teste** mit drei verschiedenen Tokens (Patient, Doctor, Superuser):

```bash
# Als Patient:
curl http://localhost:8080/api/role-demo/greeting \
  -H "Authorization: Bearer <patient-token>"

# Als Doctor:
curl http://localhost:8080/api/role-demo/greeting \
  -H "Authorization: Bearer <doctor-token>"

# Als Superuser:
curl http://localhost:8080/api/role-demo/greeting \
  -H "Authorization: Bearer <admin-token>"
```

**Frage:** Welche Antwort erhältst du jeweils? Warum ist diese Art der rollenbasierten Logik nützlich?

**Bonus:** Erweitere den Endpoint so, dass er für PATIENTs auch `userId` zurückgibt, damit der Patient nur auf seine eigenen Daten zugreifen kann:
```java
if ("PATIENT".equals(user.getRole())) {
    return ResponseEntity.ok(Map.of(
        "message", message,
        "yourPatientId", user.getUserId()
    ));
}
```
