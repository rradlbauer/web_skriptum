# 01.0 Client-Server-Computing

Fast alle Web-Applikationen folgen dem **Client-Server-Modell**. Dieses Kapitel erklärt die Grundbegriffe: Was ist ein Server, was ist ein Client, und wie arbeiten sie zusammen?

## Was ist ein Client?

Ein **Client** ist ein Programm, das eine Dienstleistung **anfordert**. Im Web ist der Client meist der **Browser** (Chrome, Firefox, Edge), der eine Webseite oder Daten anfordert und die Antwort anzeigt.

Beispiele für Clients:

- Der Browser, wenn du `http://localhost:8080/` aufrufst
- Eine Mobile-App, die Daten von einem Server lädt
- Ein Skript mit der `fetch`-API, das eine REST-Schnittstelle abfragt

Der Client **initiiert** die Kommunikation: Er sendet eine Anfrage (**Request**) und wartet auf die Antwort (**Response**).

## Was ist ein Server?

Ein **Server** ist ein Programm (oder ein Rechner, auf dem dieses Programm läuft), das Dienstleistungen **bereitstellt**. Er wartet dauerhaft auf Anfragen und beantwortet diese.

Beispiele für Server:

- Ein **Webserver** (z. B. Tomcat, das in Spring Boot eingebaut ist), der HTML-Seiten ausliefert
- Ein **Anwendungsserver**, der Geschäftslogik ausführt
- Ein **Datenbankserver** (z. B. MySQL), der Daten speichert und liefert
- Ein **REST-API-Server**, der Daten als JSON liefert

## Das Client-Server-Modell im Überblick

```
+----------+   Request (Anfrage)    +----------+
|  Client  | ---------------------> |  Server  |
| (Browser)|                        |(Web/App) |
|          | <--------------------- |          |
+----------+    Response (Antwort)  +----------+
```

Wesentliche Eigenschaften:

- Der **Client** fragt an, der **Server** antwortet
- Der Server bedient **viele Clients** gleichzeitig
- Der Server ist **dauerhaft erreichbar**, der Client verbindet sich bei Bedarf
- Der Client kann die angeforderte Ressource **an einem zentralen Ort** abrufen, ohne sie selbst zu speichern
- Häufig ist ein Server selbst Client für einen anderen Server (z.B. ein Web-Server als Client für einen Datenbank-Server)

## Client vs. Server – Zusammenfassung der Rollen

| Aspekt | Client | Server |
|--------|--------|--------|
| Initiative | Fragt an (Request) | Wartet, antwortet (Response) |
| Erreichbarkeit | Nur während der Verbindung | Dauerhaft erreichbar |
| Beispiele | Browser, Mobile-App | Webserver, API-Server, Datenbankserver |
| Benutzerinteraktion | Ja (Anzeige, Eingaben) | Nein (dient Clients) |

## Beispiel: Patientenverwaltung

Denke an eine **Patientenverwaltung** im Krankenhaus:

- Der **Client** ist der Browser, mit dem eine Pflegekraft die Patientendaten öffnet
- Der **Server** ist die Spring-Boot-Anwendung, die die Daten aus der Datenbank lädt und als HTML oder JSON an den Browser liefert
- Die **Datenbank** speichert die Patientendaten dauerhaft

Der Browser (Client) schickt eine Anfrage an den Server; der Server holt die Daten aus der Datenbank und schickt sie zurück an den Browser.

## Zusammenfassung

### Wichtige Begriffe
- Client, Server
- Request (Anfrage), Response (Antwort)
- Client-Server-Modell
- Webserver, Anwendungsserver, Datenbankserver

### Das sollst du können
- Erklären, was ein Client und was ein Server ist
- Die Rollen und Aufgaben von Client und Server unterscheiden
- Das Client-Server-Modell auf eine konkrete Anwendung (z. B. Patientenverwaltung) anwenden
