# 02.0 – Spring Boot Projektstruktur

## Einführung

In diesem Kapitel untersuchen wir die **Projektstruktur** unseres Clinical Diary Backends. Ihr werdet sehen, wie ein Spring Boot Projekt mit Maven aufgebaut ist und welche **Abhängigkeiten** (Dependencies) für unser Projekt relevant sind.

> **Vergleich zu Thymeleaf-Projekten**: Bisher habt ihr `spring-boot-starter-thymeleaf` als Abhängigkeit verwendet, um serverseitig gerendertes HTML zu erhalten. In diesem Projekt verwenden wir stattdessen `spring-boot-starter-web` – der Server liefert nur **JSON-Daten**, kein HTML.

## Maven-Projektstruktur

Ein typisches Maven/Spring Boot Projekt folgt diesem **Verzeichnisbaum**:

```
clinical-diary/
├── backend/
│   ├── pom.xml                          # Maven-Konfiguration (Abhängigkeiten, Plugins)
│   └── src/
│       └── main/
│           ├── java/
│           │   └── com/clinicaldiary/
│           │       ├── ClinicalDiaryApplication.java   # Einstiegspunkt
│           │       ├── config/                         # Security- & Daten-Konfiguration
│           │       ├── controller/                     # REST-Controller
│           │       ├── entity/                         # JPA-Entitäten
│           │       ├── repository/                     # Spring Data Repositories
│           │       └── security/                       # JWT-Authentifizierung
│           └── resources/
│               ├── application.properties              # Anwendungskonfiguration
│               └── static/                            # Statische Frontend-Dateien
│                   ├── index.html
│                   ├── css/styles.css
│                   └── js/app.js
├── frontend/
│   └── ts/
│       └── app.ts                       # TypeScript Quellcode (SPA)
└── Skriptum/                            # Dieses Skriptum
```

### Die drei wichtigen Verzeichnisse

| Verzeichnis | Zweck |
|-------------|-------|
| `src/main/java/` | Java-Quellcode (Controller, Entities, Repositories, Security) |
| `src/main/resources/` | Konfigurationsdateien und statische Assets |
| `src/main/resources/static/` | Frontend-Dateien (HTML, CSS, JS) – direkt vom Server serviert |

## Die pom.xml – Abhängigkeiten

Die `pom.xml` ist das Herzstück der Maven-Konfiguration. Sie definiert, welche **Bibliotheken** und **Frameworks** das Projekt verwendet:

```xml
<parent>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-parent</artifactId>
    <version>3.4.1</version>
</parent>

<properties>
    <java.version>24</java.version>
    <jjwt.version>0.12.6</jjwt.version>
</properties>

<dependencies>
    <!-- Web-API (kein Thymeleaf!) -->
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-web</artifactId>
    </dependency>

    <!-- JPA & Hibernate -->
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-data-jpa</artifactId>
    </dependency>

    <!-- Spring Security -->
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-security</artifactId>
    </dependency>

    <!-- Validierung -->
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-validation</artifactId>
    </dependency>

    <!-- H2 In-Memory Datenbank -->
    <dependency>
        <groupId>com.h2database</groupId>
        <artifactId>h2</artifactId>
        <scope>runtime</scope>
    </dependency>

    <!-- JWT Bibliothek -->
    <dependency>
        <groupId>io.jsonwebtoken</groupId>
        <artifactId>jjwt-api</artifactId>
        <version>${jjwt.version}</version>
    </dependency>
</dependencies>
```

### Was macht jeder Starter?

| Starter / Dependency | Zweck |
|----------------------|-------|
| **spring-boot-starter-web** | Bietet `@RestController`, `@RequestMapping`, **Tomcat** als Webserver und **Jackson** für JSON-Serialisierung |
| **spring-boot-starter-data-jpa** | Bietet `JpaRepository`, `@Entity`, Hibernate als JPA-Implementierung |
| **spring-boot-starter-security** | Bietet Sicherheitsfilter, Passwort-Hashing (`PasswordEncoder`), Authentifizierung |
| **spring-boot-starter-validation** | Bietet `@Valid`, `@NotNull`, `@Size` für Eingabevalidierung |
| **h2** | Leichte **In-Memory-Datenbank** für Entwicklung und Tests |
| **jjwt-api** | Bibliothek zum Erstellen und Validieren von **JWT-Tokens** |

> **Wichtig**: Das Projekt verwendet `spring-boot-starter-web` **statt** `spring-boot-starter-thymeleaf`. Das ist der fundamentale Unterschied: Statt HTML-Templates wird **JSON** ausgeliefert.

## Der Einstiegspunkt: ClinicalDiaryApplication.java

Jedes Spring Boot Projekt hat eine **Hauptklasse** mit der `@SpringBootApplication`-Annotation:

```java
package com.clinicaldiary;

import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;

@SpringBootApplication
public class ClinicalDiaryApplication {

    public static void main(String[] args) {
        SpringApplication.run(ClinicalDiaryApplication.class, args);
    }
}
```

Was passiert hier?

1. **`@SpringBootApplication`** ist eine **Metapher-Annotation** – sie kombiniert drei Annotationen:
   - `@Configuration`: Diese Klasse ist eine Spring-Konfiguration
   - `@EnableAutoConfiguration`: Spring konfiguriert sich automatisch
   - `@ComponentScan`: Spring scannt das Package `com.clinicaldiary` und alle Unterpakete nach annotierten Klassen

2. **`SpringApplication.run()`** startet den **Embedded Tomcat-Server** und die gesamte Spring-Applikation

3. Der **Package-Name** `com.clinicaldiary` ist entscheidend – von hier aus werden alle Unterpakete (`controller/`, `entity/`, `repository/`, etc.) automatisch gefunden

## Die application.properties

Die Konfigurationsdatei `application.properties` legt fest, wie sich die Anwendung verhält:

```properties
spring.application.name=Clinical Diary

# H2 In-Memory Datenbank
spring.datasource.url=jdbc:h2:mem:clinicaldiary
spring.datasource.driver-class-name=org.h2.Driver
spring.datasource.username=sa
spring.datasource.password=

# JPA / Hibernate
spring.jpa.database-platform=org.hibernate.dialect.H2Dialect
spring.jpa.hibernate.ddl-auto=create-drop
spring.jpa.show-sql=false

# H2 Konsole (zugänglich unter /h2-console)
spring.h2.console.enabled=true
spring.h2.console.path=/h2-console

# JWT
app.jwt.secret=clinical-diary-super-secret-key-that-is-long-enough-for-hs256-algorithm!!
app.jwt.expiration-ms=86400000
```

### Wichtige Einstellungen erklärt

| Eigenschaft | Bedeutung |
|-------------|-----------|
| `spring.datasource.url=jdbc:h2:mem:clinicaldiary` | H2 als **In-Memory-Datenbank** – Daten gehen bei Neustart verloren |
| `spring.jpa.hibernate.ddl-auto=create-drop` | Hibernate erstellt Tabellen beim Start und löscht sie beim Stoppen |
| `spring.h2.console.enabled=true` | Die **H2-Konsole** ist unter `http://localhost:8080/h2-console` erreichbar |
| `app.jwt.secret` | Geheimer Schlüssel für die JWT-Signierung |
| `app.jwt.expiration-ms=86400000` | JWT-Token gültig für 24 Stunden (86400000 ms) |

## Package-Struktur

Die Packages sind nach **Verantwortlichkeitsbereichen** (Concerns) organisiert:

```
com.clinicaldiary/
├── ClinicalDiaryApplication.java    # Einstiegspunkt
├── config/                           # Konfigurationsklassen
│   ├── DataInitializer.java         # Beispieldaten beim Start
│   └── SecurityConfig.java          # Security- & CORS-Einstellungen
├── controller/                       # REST-Controller (API-Endpoints)
│   ├── AuthController.java          # Login, Registrierung
│   ├── PatientController.java       # Patienten-Aktionen
│   ├── DoctorController.java        # Ärzte-Aktionen
│   └── SuperuserController.java     # Admin-Funktionen
├── entity/                           # JPA-Entitäten (Datenbanktabellen)
│   ├── Patient.java
│   ├── Doctor.java
│   ├── HealthRecord.java
│   ├── DoctorPatient.java           # Zuordnung Arzt-Patient
│   ├── RecordConfirmation.java      # Arzt-Bestätigung
│   ├── RecordIcd10.java             # ICD-10-Zuordnung
│   └── Icd10Code.java              # ICD-10-Katalog
├── repository/                       # Spring Data Repositories (Datenbankzugriff)
│   ├── PatientRepository.java
│   ├── DoctorRepository.java
│   ├── HealthRecordRepository.java
│   ├── DoctorPatientRepository.java
│   ├── RecordConfirmationRepository.java
│   ├── RecordIcd10Repository.java
│   └── Icd10CodeRepository.java
└── security/                         # JWT & Authentifizierung
    ├── JwtTokenProvider.java        # Token erzeugen & validieren
    ├── JwtAuthenticationFilter.java # Filter für jeden Request
    └── UserPrincipal.java           # Benutzer-Principal für Security
```

### Warum diese Trennung?

| Package | Verantwortung | Analogie aus der Thymeleaf-Welt |
|---------|---------------|--------------------------------|
| `controller/` | Empfängt HTTP-Requests, gibt JSON zurück | `@Controller` mit `@GetMapping` – aber statt `Model` → `ResponseEntity` |
| `entity/` | Datenbankmodelle | Identisch zu Thymeleaf-Projekten |
| `repository/` | Datenbankzugriff via Spring Data | Identisch zu Thymeleaf-Projekten |
| `security/` | JWT-Authentifizierung | Neu! Bisher: Session/Cookie |
| `config/` | Anwendungskonfiguration | Bisher: `application.properties` + `WebMvcConfigurer` |

## Zusammenfassung

- Ein Spring Boot Projekt folgt der **Maven-Standardstruktur** (`pom.xml`, `src/main/java`, `src/main/resources`)
- `@SpringBootApplication` markiert den **Einstiegspunkt** und aktiviert Auto-Konfiguration
- `application.properties` konfiguriert Datenbank, JWT und weitere Einstellungen
- Die **Package-Struktur** trennt Verantwortlichkeiten sauber: Controller → Entities → Repositories → Security
- Der Hauptunterschied zu Thymeleaf: **`spring-boot-starter-web` statt `spring-boot-starter-thymeleaf`**
