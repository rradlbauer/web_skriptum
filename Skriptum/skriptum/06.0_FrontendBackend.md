# 06.0 – Frontend-Backend Integration

## Die Fetch API

Die **Fetch API** ist das zentrale Werkzeug für HTTP-Anfragen aus dem Browser. Sie ist in jedem modernen Browser verfügbar und arbeitet mit **Promises**:

```typescript
// GET-Anfrage
const response = await fetch('/api/patients');
const data = await response.json();

// POST-Anfrage
await fetch('/api/health-records', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ category: 'ILLNESS', title: 'Erkältung' })
});
```

Im Clinical Diary wird Fetch durch eine **Hilfsfunktion** `api()` gekapselt.

---

## Die api()-Funktion – Zentraler HTTP-Client

Statt bei jedem Aufruf Header und Token manuell zu konfigurieren, gibt es eine zentrale Helferfunktion:

```typescript
async function api(method: string, url: string, body?: any): Promise<any> {
    const headers: Record<string, string> = { "Content-Type": "application/json" };
    if (state.token) {
        headers["Authorization"] = "Bearer " + state.token;
    }
    const opts: RequestInit = { method, headers };
    if (body) opts.body = JSON.stringify(body);

    const response = await fetch(url, opts);
    const data = await response.json();
    if (!response.ok) {
        throw new Error(data.error || "Request failed");
    }
    return data;
}
```

Was macht diese Funktion?

| Schritt | Erklärung |
|---------|-----------|
| Header setzen | `Content-Type: application/json` – sagt dem Server, dass JSON gesendet wird |
| Token anhängen | Falls ein JWT Token vorhanden ist, wird er als `Authorization: Bearer ...` mitgeschickt |
| Body serialisieren | JavaScript-Objekt wird zu JSON-String konvertiert (`JSON.stringify`) |
| Fetch aufrufen | Die eigentliche HTTP-Anfrage |
| Antwort parsen | `response.json()` – JSON-Antwort wird zu JavaScript-Objekt |
| Fehler prüfen | Bei HTTP-Status 4xx/5xx wird ein Error geworfen |

**Verwendung im Code:**

```typescript
// Einfach und lesbar:
const records = await api("GET", "/api/patients/me/records");
const loginData = await api("POST", "/api/auth/login", { email, password });
await api("PUT", `/api/patients/me/records/${id}`, updatedRecord);
await api("DELETE", `/api/patients/me/records/${id}`);
```

## HTTP-Methoden im Überblick

### GET – Daten laden

```typescript
// Alle Health Records des Patienten laden
const records = await api("GET", "/api/patients/me/records");
// Gibt ein Array von Record-Objekten zurück

// Einzelnen Arzt laden
const doctor = await api("GET", `/api/doctors/me/patients/${patientId}/records`);
```

### POST – Daten erstellen

```typescript
// Login: E-Mail und Passwort senden
const loginData = await api("POST", "/api/auth/login", {
    email: "anna.schmidt@email.at",
    password: "password123"
});
// Antwort: { token: "...", role: "PATIENT", userId: 1, name: "Anna Schmidt" }

// Neuen Health Record erstellen
await api("POST", "/api/patients/me/records", {
    category: "ILLNESS",
    title: "Erkältung",
    description: "Schnupfen und Halsschmerzen",
    dateFrom: "2025-06-01",
    severity: "Mild"
});
```

### PUT – Daten aktualisieren

```typescript
// Bestehenden Record aktualisieren
await api("PUT", `/api/patients/me/records/${recordId}`, {
    title: "Erkältung (aktualisiert)",
    severity: "Moderate"
});
```

### DELETE – Daten löschen

```typescript
// Record löschen
await api("DELETE", `/api/patients/me/records/${recordId}`);
```

## JSON – Der Datenaustausch

**Request Body** (TypeScript → Server):

```typescript
// JavaScript-Objekt
{ email: "anna@email.at", password: "secret" }

// Wird serialisiert zu:
'{"email":"anna@email.at","password":"secret"}'
```

**Response** (Server → TypeScript):

```json
{
    "token": "eyJhbGciOiJIUzI1NiJ9...",
    "role": "PATIENT",
    "userId": 1,
    "name": "Anna Schmidt"
}
```

`response.json()` konvertiert diesen JSON-String automatisch zu einem JavaScript-Objekt.

## Fehlerbehandlung

Alle API-Aufrufe sind in **try/catch**-Blöcken gekapselt:

```typescript
try {
    const records = await api("GET", "/api/patients/me/records");
    content.innerHTML = records.map(r => renderRecordCard(r, true)).join("");
} catch (e: any) {
    content.innerHTML = `<div class="alert alert-error">${e.message}</div>`;
}
```

Die `api()`-Funktion wirft einen Error bei nicht-erfolgreichen HTTP-Statuscodes:

```typescript
if (!response.ok) {
    throw new Error(data.error || "Request failed");
}
```

Fehlermeldungen werden direkt im UI angezeigt – der User sieht rote Alert-Boxen mit der Fehlermeldung.

## Der Login-Flow im Detail

```
1. User klickt "Login"
        ↓
2. Email und Passwort werden aus den Input-Feldern gelesen
        ↓
3. api("POST", "/api/auth/login", { email, password }) wird aufgerufen
        ↓
4. Server prüft Credentials → erzeugt JWT Token
        ↓
5. Antwort wird in saveSession() gespeichert:
   - state.token = data.token
   - state.role = data.role  
   - localStorage.setItem("token", data.token)
        ↓
6. render() wird aufgerufen
        ↓
7. render() erkennt: state.token existiert → ruft navigatePatient() auf
        ↓
8. Patienten-Dashboard wird angezeigt
```

```typescript
// Login-Handler
document.getElementById("btn-login")!.addEventListener("click", async () => {
    const email = (document.getElementById("login-email") as HTMLInputElement).value;
    const password = (document.getElementById("login-password") as HTMLInputElement).value;
    try {
        const data = await api("POST", "/api/auth/login", { email, password });
        saveSession(data);  // Token und User-Daten speichern
        render();           // Ansicht wechseln
    } catch (e: any) {
        document.getElementById("login-error")!.innerHTML =
            `<div class="alert alert-error">${e.message}</div>`;
    }
});
```

## Der Data-Loading-Flow

```
1. navigatePatient() wird aufgerufen
        ↓
2. Tab-Buttons werden gerendert (innerHTML)
        ↓
3. renderPatientRecords() wird aufgerufen
        ↓
4. api("GET", "/api/patients/me/records") lädt Daten
        ↓
5. Für jeden Record wird renderRecordCard() aufgerufen
        ↓
6. Fertiges HTML wird in #tab-content geschrieben
```

```typescript
async function renderPatientRecords() {
    const content = document.getElementById("tab-content")!;
    try {
        const records = await api("GET", "/api/patients/me/records");
        let html = `<div class="card-header">
                        <h2>Health Records</h2>
                        <button class="btn btn-primary" id="btn-new-record">+ New Record</button>
                     </div>
                     <div id="records-list">`;
        
        if (records.length === 0) {
            html += `<div class="empty-state"><p>No health records yet.</p></div>`;
        } else {
            for (const r of records) {
                html += renderRecordCard(r, true);
            }
        }
        html += `</div>`;
        content.innerHTML = html;

        // Event Listener für "New Record" Button
        document.getElementById("btn-new-record")!.addEventListener("click", () => showRecordModal(null));
    } catch (e: any) {
        content.innerHTML = `<div class="alert alert-error">${e.message}</div>`;
    }
}
```

## Modal Dialogs

Modals werden **dynamisch erstellt** und ans `document.body` angehängt:

```typescript
function showRecordModal(record: any | null) {
    const isEdit = record !== null;
    const modal = document.createElement("div");
    modal.className = "modal-overlay";
    modal.innerHTML = `
        <div class="modal">
            <h2>${isEdit ? "Edit Record" : "New Health Record"}</h2>
            <div class="form-group">
                <label>Category</label>
                <select id="m-category">
                    <option value="ILLNESS">Illness</option>
                    <option value="VACCINATION">Vaccination</option>
                    <option value="MEDICATION">Medication</option>
                </select>
            </div>
            <!-- ... weitere Formularfelder ... -->
            <div class="modal-actions">
                <button class="btn btn-outline" id="m-cancel">Cancel</button>
                <button class="btn btn-primary" id="m-save">${isEdit ? "Save" : "Create"}</button>
            </div>
        </div>`;

    document.body.appendChild(modal);

    // Modal schließen
    modal.querySelector("#m-cancel")!.addEventListener("click", () => modal.remove());
    modal.addEventListener("click", (e) => { if (e.target === modal) modal.remove(); });

    // Speichern
    modal.querySelector("#m-save")!.addEventListener("click", async () => {
        const body = {
            category: (modal.querySelector("#m-category") as HTMLSelectElement).value,
            title: (modal.querySelector("#m-title") as HTMLInputElement).value,
            // ... weitere Felder
        };
        try {
            if (isEdit) {
                await api("PUT", `/api/patients/me/records/${record.id}`, body);
            } else {
                await api("POST", "/api/patients/me/records", body);
            }
            modal.remove();
            renderPatientRecords();  // Liste aktualisieren
        } catch (e: any) {
            alert(e.message);
        }
    });
}
```

## Zusammenfassung

| Konzept | Beschreibung |
|---------|-------------|
| **api()** | Zentrale Helferfunktion für alle HTTP-Anfragen mit JWT-Header |
| **GET** | Daten vom Server laden |
| **POST** | Neue Daten erstellen (Login, neuer Record) |
| **PUT** | Bestehende Daten aktualisieren |
| **DELETE** | Daten löschen |
| **JSON** | Format für Datenaustausch zwischen Frontend und Backend |
| **try/catch** | Fehlerbehandlung mit Anzeige im UI |
| **Modal** | Dynamisch erstellte Dialoge für Formulare |
| **saveSession()** | Speichert Token und User-Infos in state + localStorage |
