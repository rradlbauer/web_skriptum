# 04.1 - JWT (JSON Web Token)

Im vorherigen Kapitel haben wir gesehen, dass Spring Security die Authentifizierung managed. Aber **wie** wird das JWT-Token eigentlich erzeugt und validiert? Das kümmert sich die `JwtTokenProvider`-Klasse.

## Was ist JWT?

**JWT (JSON Web Token)** ist ein offener Standard (RFC 7519) für den sicheren Austausch von Informationen zwischen Parteien als JSON-Objekt. JWTs werden häufig für **Authentication** verwendet, weil sie:

- **Selbst enthalten** sind – alle nötigen Daten (User-ID, E-Mail, Rolle) sind im Token
- **Signiert** sind – der Server kann die Echtheit prüfen
- **Zustandslos** sind – der Server muss nichts speichern

## Die JWT-Struktur

Ein JWT-Token besteht aus **drei Teilen**, getrennt durch Punkte:

```
Header.Payload.Signature
```

Jeder Teil ist **Base64URL-kodiert**:

```
eyJhbGciOiJIUzUxMiJ9.eyJzdWIiOiJwYXRpZW50QGV4YW1wbGUuYXQiLCJ1c2VySWQiOjEsInJvbGUiOiJQQVRJRU5UIiwiaWF0IjoxNzAwMDAwMDAwLCJleHAiOjE3MDAxMDAwMDB9.HASH-signature
```

### 1. Header

Enthält den verwendeten **Signing-Algorithmus**:

```json
{
  "alg": "HS512",
  "typ": "JWT"
}
```

### 2. Payload (Claims)

Enthält die eigentlichen **Daten** (Claims). Unser Projekt verwendet diese Claims:

```json
{
  "sub": "patient@example.com",     // Subject (E-Mail)
  "userId": 1,                      // Benutzer-ID
  "role": "PATIENT",                // Rolle
  "iat": 1700000000,                // Issued At (Erstellungszeitpunkt)
  "exp": 1700100000                 // Expiration (Ablaufzeit)
}
```

> **Achtung:** Das Payload ist **nicht verschlüsselt**, sondern nur Base64-kodiert! Jeder kann den Inhalt lesen. Speichere daher **keine sensiblen Daten** im JWT-Payload (z.B. kein Passwort, keine Diagnosen).

### 3. Signature

Die **Signatur** stellt sicher, dass der Token nicht verändert wurde:

```
HMAC-SHA512(
  base64UrlEncode(header) + "." + base64UrlEncode(payload),
  secretKey
)
```

Nur der Server kennt den `secretKey` – niemand kann also einen gefälschten Token erstellen.

## Die JwtTokenProvider-Klasse

```java
@Component
public class JwtTokenProvider {

    private final SecretKey key;
    private final long expirationMs;

    public JwtTokenProvider(
            @Value("${app.jwt.secret}") String secret,
            @Value("${app.jwt.expiration-ms}") long expirationMs) {
        this.key = Keys.hmacShaKeyFor(secret.getBytes(StandardCharsets.UTF_8));
        this.expirationMs = expirationMs;
    }
```

### Konstruktor

Die Konfiguration kommt aus `application.properties`:

```properties
app.jwt.secret=clinical-diary-super-secret-key-that-is-long-enough-for-hs256-algorithm!!
app.jwt.expiration-ms=86400000
```

- **`app.jwt.secret`**: Der geheime Schlüssel für die Signierung. Muss für HMAC-SHA512 mindestens 64 Zeichen lang sein.
- **`app.jwt.expiration-ms`**: Ablaufzeit in Millisekunden. `86400000` = 24 Stunden.

> **Sicherheitshinweis:** Der Secret Key darf **niemals** im Quellcode hartkodiert werden! In Produktion wird er aus Umgebungsvariablen gelesen.

### `generateToken()` – Token erstellen

```java
public String generateToken(Long userId, String email, String role) {
    Date now = new Date();
    Date expiryDate = new Date(now.getTime() + expirationMs);

    return Jwts.builder()
            .subject(email)                // "sub" Claim = E-Mail
            .claim("userId", userId)       // Custom Claim
            .claim("role", role)           // Custom Claim: "PATIENT", "DOCTOR", "SUPERUSER"
            .issuedAt(now)                 // "iat" Claim
            .expiration(expiryDate)        // "exp" Claim
            .signWith(key)                 // Signierung mit HMAC-SHA512
            .compact();                    // Base64URL-Kodierung
}
```

Die Methode erstellt ein JWT mit drei **Custom Claims** (`userId`, `role`) und den Standard-Claims (`sub`, `iat`, `exp`).

### Claims auslesen

```java
public String getEmailFromToken(String token) {
    return Jwts.parser()
            .verifyWith(key)                    // Schlüssel für Verifikation
            .build()
            .parseSignedClaims(token)           // Token parsen + Signatur prüfen
            .getPayload()
            .getSubject();                      // "sub" = E-Mail
}

public Long getUserIdFromToken(String token) {
    return Jwts.parser()
            .verifyWith(key).build()
            .parseSignedClaims(token)
            .getPayload()
            .get("userId", Long.class);         // Custom Claim auslesen
}

public String getRoleFromToken(String token) {
    return Jwts.parser()
            .verifyWith(key).build()
            .parseSignedClaims(token)
            .getPayload()
            .get("role", String.class);         // Custom Claim auslesen
}
```

Jede Methode:
1. Erstellt einen Parser mit dem geheimen Schlüssel
2. Parst und **verifiziert** den Token (Signatur-Check)
3. Liest den gewünschten Wert aus dem Payload

### `validateToken()` – Token prüfen

```java
public boolean validateToken(String token) {
    try {
        Jwts.parser().verifyWith(key).build().parseSignedClaims(token);
        return true;   // Token gültig
    } catch (JwtException | IllegalArgumentException e) {
        return false;  // Token ungültig (abgelaufen, gefälscht, etc.)
    }
}
```

Mögliche Fehlerquellen:
- **`ExpiredJwtException`**: Token ist abgelaufen
- **`SignatureException`**: Signatur stimmt nicht überein (Key falsch oder Token gefälscht)
- **`MalformedJwtException`**: Token-Format ist ungültig

## Der Login-Flow im AuthController

```java
@PostMapping("/login")
public ResponseEntity<?> login(@RequestBody Map<String, String> body) {
    String email = body.get("email");
    String password = body.get("password");

    // 1. Patient suchen
    var patientOpt = patientRepo.findByEmail(email);
    if (patientOpt.isPresent()) {
        Patient patient = patientOpt.get();
        if (passwordEncoder.matches(password, patient.getPassword())) {
            // 2. Passwort stimmt → JWT generieren
            String token = jwtTokenProvider.generateToken(
                patient.getId(), patient.getEmail(), "PATIENT");
            // 3. Token + Metadaten zurückgeben
            return ResponseEntity.ok(Map.of(
                "token", token, "role", "PATIENT",
                "userId", patient.getId(),
                "name", patient.getFirstName() + " " + patient.getLastName()
            ));
        }
    }

    // ... gleiche Logik für Doctor ...

    // Superuser (Hardcoded für Entwicklung):
    if ("admin@clinicaldiary.at".equals(email) && "admin".equals(password)) {
        String token = jwtTokenProvider.generateToken(0L, email, "SUPERUSER");
        return ResponseEntity.ok(Map.of(
            "token", token, "role", "SUPERUSER",
            "userId", 0L, "name", "Administrator"
        ));
    }

    return ResponseEntity.status(401).body(Map.of("error", "Invalid email or password"));
}
```

Der Ablauf:
1. **Email + Passwort** werden empfangen
2. Zuerst wird in der **Patient-Tabelle** gesucht, dann in der **Doctor-Tabelle**
3. Falls gefunden: Passwort mit `passwordEncoder.matches()` vergleichen
4. Bei Übereinstimmung: **JWT generieren** und zurückgeben
5. Bei keiner Übereinstimmung: **401 Unauthorized** zurückschicken

## Speicherung auf dem Frontend

Das Frontend speichert das Token im **localStorage** und sendet es bei jedem Request:

```javascript
// Login-Aufruf (vereinfacht):
const response = await fetch('/api/auth/login', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ email, password })
});
const data = await response.json();
localStorage.setItem('token', data.token);

// Jeder nachfolgende API-Call:
const token = localStorage.getItem('token');
fetch('/api/patient/1/diary', {
    headers: { 'Authorization': 'Bearer ' + token }
});
```

## Bibliothek: jjwt

Wir verwenden die Bibliothek **io.jsonwebtoken** (jjwt):

```xml
<!-- In der pom.xml: -->
<dependency>
    <groupId>io.jsonwebtoken</groupId>
    <artifactId>jjwt-api</artifactId>
    <version>0.12.6</version>
</dependency>
```

Die wichtigsten Klassen:
- **`Jwts.builder()`** – Erstellt ein neues JWT
- **`Jwts.parser()`** – Parst und validiert ein JWT
- **`Keys.hmacShaKeyFor()`** – Erstellt einen HMAC-Schlüssel aus einem String
