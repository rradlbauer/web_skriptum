# 01.0 – Überblick über die Applikation

## Was ist das Clinical Diary?

Das **Clinical Diary** ist eine Web-Applikation, in der Patienten ihre Gesundheitsdaten digital erfassen und verwalten können. Ärzte können diese Daten einsehen, bestätigen und mit medizinischen Codes (ICD-10) versehen.

## Benutzerrollen

Das System unterscheidet drei Benutzerrollen:

| Rolle | Beschreibung |
|-------|-------------|
| **Patient** | Verwaltet eigene Gesundheitsdaten, sucht und weist Ärzte zu |
| **Arzt** | Sieht zugewiesene Patienten, bestätigt Einträge, vergibt ICD-10-Codes |
| **Superuser** | Registriert Ärzte, aktiviert/deaktiviert Ärzte, sieht Statistiken |

## Funktionen im Detail

### Patient

- **Registrieren & Einloggen**
- **Gesundheitsdaten anlegen**: Krankheit, Impfung, Medikament, Sonstiges
- **Einträge bearbeiten & löschen**
- **Ärzte suchen & zuweisen**: Ein Arzt kann einem Eintrag zugewiesen werden
- **Eigenen Arzt suchen**: Ärzte nach Name oder Fachrichtung durchsuchen

### Arzt

- **Einloggen**
- **Zugewiesene Patienten einsehen**: Liste aller Patienten, die dem Arzt zugewiesen wurden
- **Einträge bestätigen**: Eintrag als medizinisch bestätigt markieren
- **ICD-10-Codes zuweisen**: Medizinischen Diagnosecode ergänzen
- **Kommentare hinterlassen**

### Superuser

- **Ärzte registrieren**: Neue Ärzte im System anlegen
- **Ärzte aktivieren/deaktivieren**: Zugang ein- oder ausschalten
- **Statistiken einsehen**: Anzahl Patienten, Ärzte, Einträge etc.

## Architektur

Das Clinical Diary folgt einer **Drei-Schichten-Architektur** mit client-seitigem Rendering:

```
Browser (TypeScript SPA)
       |
       | HTTP (JSON + JWT)
       |
Spring Boot (REST API)
       |
       | JPA
       |
H2 Database
```

### Unterschied zu Thymeleaf

Bisher habt ihr so gearbeitet:

```
Browser  -->  Spring Boot (Controller + Thymeleaf)  -->  Datenbank
                 |
                 +--> HTML wird hier generiert
```

Hier arbeitet ihr so:

```
Browser (TypeScript)  <--JSON-->  Spring Boot (REST API)  -->  Datenbank
     |                                   |
     +--> HTML wird hier generiert       +--> Nur Daten, kein HTML
```

**Vorteile dieses Ansatzes:**
- Frontend und Backend sind **entkoppelt**
- Das Frontend kann **unabhängig** entwickelt werden
- Die API kann von **verschiedenen Clients** genutzt werden (Web, Mobile, etc.)
- Weniger Last auf dem Server
