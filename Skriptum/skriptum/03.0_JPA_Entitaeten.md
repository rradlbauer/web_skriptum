# 03.0 – JPA Entitäten & Spring Data Repositories

## Einführung

Dieses Kapitel behandelt die **Datenbankmodelle** (Entitäten) und den **Datenbankzugriff** (Repositories) unseres Clinical Diary Projekts. Ihr kennt JPA-Grundlagen bereits – hier geht es um die konkrete Anwendung im Projekt.

## JPA-Grundlagen – Auffrischung

### Die wichtigsten Annotationen

| Annotation | Zweck |
|------------|-------|
| `@Entity` | Markiert eine Klasse als Datenbank-Tabelle |
| `@Table(name = "...")` | Legt den Tabellennamen fest |
| `@Id` | Markiert den Primärschlüssel |
| `@GeneratedValue(strategy = GenerationType.IDENTITY)` | Automatische ID-Inkrementierung |
| `@Column(unique = true, nullable = false)` | Spalten-Einschränkungen |

## Warum ohne Lombok?

Dieses Projekt verwendet **keine Lombok-Annotationen** wie `@Data`, `@Getter` oder `@Setter`. Der Grund ist **didaktisch**: Explizite Getter und Setter machen den Code transparenter und helfen euch, die Struktur von JPA-Entitäten zu verstehen.

```java
// So sieht eine Entität im Projekt aus (explizit):
public Long getId() { return id; }
public void setId(Long id) { this.id = id; }

// Mit Lombok wäre es kompakter, aber weniger transparent:
// @Getter @Setter → generiert die Methoden automatisch
```

## Alle Entitäten im Projekt

### 1. Patient

Die Patienten-Entität repräsentiert einen **Patienten** im System:

```java
@Entity
@Table(name = "patients")
public class Patient {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Column(unique = true, nullable = false)
    private String email;

    @Column(nullable = false)
    private String password;

    @Column(unique = true, nullable = false)
    private String ssn;              // Sozialversicherungsnummer

    @Column(nullable = false)
    private String firstName;

    @Column(nullable = false)
    private String lastName;

    private String dateOfBirth;

    // Standard-Konstruktor (von JPA benötigt)
    public Patient() {}

    // Getter und Setter für alle Felder...
}
```

| Feld | Typ | Beschreibung |
|------|-----|-------------|
| `id` | `Long` | Primärschlüssel, automatisch generiert |
| `email` | `String` | Eindeutig, wird für Login verwendet |
| `password` | `String` | Gehasht mit BCrypt |
| `ssn` | `String` | Sozialversicherungsnummer (einzigartig) |
| `firstName` | `String` | Vorname |
| `lastName` | `String` | Nachname |
| `dateOfBirth` | `String` | Geburtsdatum (als String gespeichert) |

## Spring Data Repositories

**Spring Data JPA** vereinfacht den Datenbankzugriff enorm – ihr definiert nur eine **Interface**, und Spring erstellt die Implementierung automatisch.

### Grundprinzip

```java
// Ihr schreibt:
public interface PatientRepository extends JpaRepository<Patient, Long> {
    Optional<Patient> findByEmail(String email);
    boolean existsByEmail(String email);
}

// Spring erstellt automatisch die Implementierung mit:
// - findById(Long id)
// - findAll()
// - save(Patient entity)
// - deleteById(Long id)
// - findByEmail(String email)   ← abgeleitete Query
// - existsByEmail(String email) ← abgeleitete Query
```

### Alle Repositories im Projekt

```java
public interface PatientRepository extends JpaRepository<Patient, Long> {
    Optional<Patient> findByEmail(String email);
    boolean existsByEmail(String email);
```

## Abgeleitete Query-Methoden

Spring Data kann **Query-Methoden** aus dem Methodennamen ableiten:

| Methode | Generierte Query |
|---------|-----------------|
| `findByEmail(String email)` | `SELECT p FROM Patient p WHERE p.email = ?1` |
| `existsByEmail(String email)` | `SELECT COUNT(*) > 0 FROM Patient p WHERE p.email = ?1` |
| `existsBySsn(String ssn)` | `SELECT COUNT(*) > 0 FROM Patient p WHERE p.ssn = ?1` |
| `findByActiveTrue()` | `SELECT d FROM Doctor d WHERE d.active = true` |
| `findByPatientIdOrderByCreatedAtDesc(Long id)` | `SELECT h FROM HealthRecord h WHERE h.patientId = ?1 ORDER BY h.createdAt DESC` |
| `findByDoctorIdAndPatientId(Long d, Long p)` | `SELECT dp FROM DoctorPatient dp WHERE dp.doctorId = ?1 AND dp.patientId = ?2` |

> **Namenskonvention**: `findBy` + Feldname + Optionale Bedingung (`True`, `OrderBy...`, `Desc`)

## @Query – Benutzerdefinierte Queries

Wenn abgeleitete Methoden nicht ausreichen, könnt ihr **eigene JPQL-Queries** schreiben:

```java
// In DoctorRepository:
@Query("SELECT d FROM Doctor d WHERE d.active = true AND " +
       "(LOWER(d.firstName) LIKE LOWER(CONCAT('%', :query, '%')) OR " +
       "LOWER(d.lastName) LIKE LOWER(CONCAT('%', :query, '%')))")
List<Doctor> search(String query);
```

```java
// In DoctorPatientRepository:
@Query("SELECT dp.patientId FROM DoctorPatient dp WHERE dp.doctorId = :doctorId")
List<Long> findPatientIdsByDoctorId(Long doctorId);
```

> **JPQL** (Java Persistence Query Language) arbeitet auf **Entitäten**, nicht auf Tabellen. `SELECT d FROM Doctor d` ist JPQL – `SELECT * FROM doctors` wäre SQL.

## H2 als In-Memory-Datenbank

Das Projekt verwendet **H2** als In-Memory-Datenbank für Entwicklung und Tests:

```properties
spring.datasource.url=jdbc:h2:mem:clinicaldiary
spring.jpa.hibernate.ddl-auto=create-drop
```

| Eigenschaft | Bedeutung |
|-------------|-----------|
| `jdbc:h2:mem:clinicaldiary` | Datenbank im **Arbeitsspeicher** – kein Dateizugriff |
| `create-drop` | Tabellen werden beim Start erstellt und beim Stoppen gelöscht |

> **Vorteil**: Keine externe Datenbank nötig, ideal für Entwicklung und Tests.
> **Nachteil**: Alle Daten gehen bei jedem Neustart verloren.

Die **Beispieldaten** werden in der `DataInitializer`-Klasse beim Start geladen:

```java
@Component
public class DataInitializer implements CommandLineRunner {
    @Override
    public void run(String... args) {
        // Erstellt Patienten, Ärzte, Gesundheitsakten, etc.
        Patient patient1 = new Patient();
        patient1.setEmail("anna.schmidt@email.at");
        patient1.setPassword(passwordEncoder.encode("password123"));
        // ...
    }
}
```

## Zusammenfassung

- **JPA-Entitäten** definieren die Datenbankstruktur mit `@Entity`, `@Id`, `@Column`
- **Spring Data Repositories** vereinfachen den Datenbankzugriff – Methoden werden aus dem Namen abgeleitet
- **`@Query`** erlaubt benutzerdefinierte JPQL-Queries für komplexe Abfragen
- **H2** ist eine In-Memory-Datenbank, ideal für Entwicklung und Tests
- Das Projekt verwendet **explizite Getter/Setter** statt Lombok für bessere Transparenz
- **`DataInitializer`** lädt Beispieldaten beim Start der Anwendung
