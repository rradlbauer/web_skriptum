# 05.1 – Single-Page Application mit TypeScript

## Was ist eine SPA?

Eine **Single-Page Application** (SPA) ist eine Webanwendung, die aus **einer einzigen HTML-Seite** besteht. Statt dass der Browser bei jeder Aktion eine neue Seite lädt, wird der Inhalt **dynamisch per JavaScript** ausgetauscht.

```
Thymeleaf-Ansatz:                    SPA-Ansatz:
┌─────────┐                          ┌─────────────────────┐
│ login.html │  → Seite laden         │   index.html        │
├─────────┤                          │   ┌───────────────┐ │
│ home.html │  → Seite laden         │   │ #main-content │ │
├─────────┤                          │   │ (Inhalt wird   │ │
│ ...      │  → Seite laden          │   │  per JS ersetzt│ │
└─────────┘                          │   └───────────────┘ │
                                     │   <script app.js>   │
                                     └─────────────────────┘
```

Im Clinical Diary-Projekt gibt es nur **eine einzige HTML-Datei**:

```html
<!-- backend/src/main/resources/static/index.html -->
<!DOCTYPE html>
<html lang="en">
<head>
    <title>Clinical Diary</title>
    <link rel="stylesheet" href="/css/styles.css">
</head>
<body>
    <div id="app">
        <nav id="navbar" class="hidden">
            <div class="nav-brand">Clinical Diary</div>
            <div class="nav-user">
                <span id="nav-user-name"></span>
                <span id="nav-user-role" class="badge"></span>
                <button id="btn-logout" class="btn btn-sm">Logout</button>
            </div>
        </nav>
        <main id="main-content">
            <!-- Views werden hier von TypeScript gerendert -->
        </main>
    </div>
    <script src="/js/app.js"></script>
</body>
</html>
```

Der gesamte Inhalt entsteht durch `app.js` – das kompilierte TypeScript.

## State Management – Der globale Zustand

Jede SPA braucht einen **zentralen Zustand**, der die aktuelle Situation der Anwendung beschreibt. Im Clinical Diary ist das das `state`-Objekt:

```typescript
interface AppState {
    token: string | null;      // JWT Token für Authentifizierung
    role: string | null;       // PATIENT, DOCTOR oder SUPERUSER
    userId: number | null;     // ID des eingeloggten Users
    name: string | null;       // Name des Users
    currentView: string;       // Aktuelle Ansicht (z.B. "patient-records")
}

const state: AppState = {
    token: localStorage.getItem("token"),
    role: localStorage.getItem("role"),
    userId: parseInt(localStorage.getItem("userId") || "0"),
    name: localStorage.getItem("name"),
    currentView: "login",
};
```

**Vergleich mit Java:** Das ist ähnlich wie ein `@SessionScope`-Bean in Spring – except dass der Zustand im **Browser** (nicht auf dem Server) gespeichert wird.

## View Rendering – Jede Ansicht ist eine Funktion

In einer SPA wird jede Ansicht durch eine **Funktion** dargestellt, die den HTML-Inhalt für `#main-content` generiert:

```typescript
const mainContent = document.getElementById("main-content") as HTMLElement;

function renderLogin() {
    mainContent.innerHTML = `
        <div class="login-container">
            <h1>Clinical Diary</h1>
            <p class="subtitle">Your personal health record</p>
            <div class="card">
                <!-- Login-Formular wird hier eingefügt -->
            </div>
        </div>`;
    // Event Listener für den Login-Button werden hier angehängt
}
```

Der Ablauf ist immer gleich:
1. **HTML-Template** wird als String erstellt
2. **innerHTML** wird gesetzt → Browser rendert das neue HTML
3. **Event Listener** werden an die neuen Elemente angehängt

## Navigation ohne Seitenreload

Die zentrale `render()`-Funktion entscheidet, welche Ansicht angezeigt wird:

```typescript
function render() {
    if (!state.token) {
        hideNavbar();
        renderLogin();          // Kein Token → Login-Seite
        return;
    }
    showNavbar();
    switch (state.role) {
        case "PATIENT":
            navigatePatient();  // Patient → Patienten-Ansicht
            break;
        case "DOCTOR":
            navigateDoctor();   // Arzt → Arzt-Ansicht
            break;
        case "SUPERUSER":
            navigateSuperuser(); // Admin → Admin-Ansicht
            break;
        default:
            renderLogin();
    }
}
```

Die `navigate()`-Funktion aktualisiert den State und ruft `render()` auf:

```typescript
function navigate(view: string) {
    state.currentView = view;
    render();
}
```

> **Vergleich mit Thymeleaf:** Statt `<a href="/records">` (Seitenreload) ruft die SPA `navigate("patient-records")` auf – der Browser lädt **keine neue Seite**, sondern JavaScript ersetzt nur den Inhalt von `#main-content`.

## Tab-Navigation in der Praxis

Jede Rolle hat eigene Tabs. Hier die Patienten-Ansicht als Beispiel:

```typescript
async function navigatePatient() {
    const tab = state.currentView;
    mainContent.innerHTML = `
        <div class="tabs">
            <button class="tab-btn ${tab === "patient-records" ? "active" : ""}" 
                    data-view="patient-records">My Records</button>
            <button class="tab-btn ${tab === "patient-doctors" ? "active" : ""}" 
                    data-view="patient-doctors">My Doctors</button>
            <button class="tab-btn ${tab === "patient-search" ? "active" : ""}" 
                    data-view="patient-search">Find Doctor</button>
        </div>
        <div id="tab-content"><div class="loading">Loading...</div></div>`;

    // Event Listener an Tab-Buttons anhängen
    document.querySelectorAll(".tab-btn").forEach(btn => {
        btn.addEventListener("click", () => {
            navigate(btn.getAttribute("data-view")!);
        });
    });

    // Inhalt des aktiven Tabs laden
    switch (tab) {
        case "patient-doctors": await renderPatientDoctors(); break;
        case "patient-search":  await renderPatientSearch(); break;
        default:                await renderPatientRecords();
    }
}
```

## DOM Manipulation

TypeScript im Browser greift direkt auf **DOM-APIs** zu:

```html
<main id="main-content">
    <!-- Hier wird der Inhalt dynamisch eingefügt -->
</main>
```

```typescript
// Element per ID finden
const mainContent = document.getElementById("main-content") as HTMLElement;

// Inhalt ersetzen
mainContent.innerHTML = `<h2>Neuer Inhalt</h2>`;

// Element per CSS-Selektor finden
const tabs = document.querySelectorAll(".tab-btn");

// Event Listener hinzufügen
document.getElementById("btn-login")!.addEventListener("click", () => {
    // Login-Logik
});
```

Der Operator `!` (Non-Null Assertion) sagt TypeScript: "Ich weiß, dass dieses Element existiert." Das ist nötig, weil `getElementById()` technisch `null` zurückgeben könnte.

## Event Handling

Events werden nach dem Rendern angehängt – weil die Elemente ja erst zur Laufzeit entstehen:

```typescript
// Login-Button: Klick-Handler nach dem Rendern
document.getElementById("btn-login")!.addEventListener("click", async () => {
    const email = (document.getElementById("login-email") as HTMLInputElement).value;
    const password = (document.getElementById("login-password") as HTMLInputElement).value;
    try {
        const data = await api("POST", "/api/auth/login", { email, password });
        saveSession(data);
        render();  // Nach erfolgreichem Login: Ansicht wechseln
    } catch (e: any) {
        document.getElementById("login-error")!.innerHTML =
            `<div class="alert alert-error">${e.message}</div>`;
    }
});

// Enter-Taste zum Login
document.getElementById("login-password")!.addEventListener("keydown", (e) => {
    if (e.key === "Enter") document.getElementById("btn-login")!.click();
});
```

## Die Initialisierung

Ganz am Ende von `app.ts` wird beim Laden der Seite entschieden, was angezeigt wird:

```typescript
if (state.token) {
    navigate("login");
    // Token vorhanden → direkt zur passenden Ansicht
    if (state.role === "PATIENT") navigate("patient-records");
    else if (state.role === "DOCTOR") navigate("doctor-patients");
    else if (state.role === "SUPERUSER") navigate("su-doctors");
} else {
    renderLogin();  // Kein Token → Login
}
```

Das sorgt dafür, dass ein User nach einem **Page Refresh** eingeloggt bleibt – der Token kommt aus `localStorage`.

---

## Zusammenfassung

| Konzept | Beschreibung |
|---------|-------------|
| **SPA** | Eine HTML-Seite, dynamischer Inhalt per JavaScript |
| **State** | Globaler Zustand im Browser (token, role, currentView) |
| **View-Funktion** | Jede Ansicht ist eine Funktion, die HTML in `#main-content` schreibt |
| **navigate()** | Aktualisiert State und ruft render() auf |
| **render()** | Zentrale Routing-Funktion: bestimmt basierend auf Token und Rolle die Ansicht |
| **Event Handling** | Events werden nach dem Rendern angehängt (nicht im HTML) |
| **localStorage** | Bleibende Speicherung im Browser (Token überlebt Refresh) |
