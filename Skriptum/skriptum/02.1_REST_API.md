# 02.1 – REST API mit Spring Boot

## Einführung

Bisher habt ihr mit Thymeleaf gearbeitet: Der Controller hat ein `Model` mit Daten befüllt und ein **HTML-Template** zurückgegeben. In diesem Projekt arbeiten wir anders – der Controller gibt **JSON-Daten** zurück, und der Browser (bzw. TypeScript-Code) rendert diese Daten selbst.

> **Kernidee**: Statt `return "template-name"` gibt ein `@RestController` ein **Java-Objekt** zurück, das automatisch in **JSON** umgewandelt wird.

## REST-Grundsätze

**REST** (Representational State Transfer) ist ein Architekturstil für Web-APIs. Die wichtigsten Prinzipien:

| Prinzip | Bedeutung | Beispiel im Projekt |
|---------|-----------|---------------------|
| **Ressourcen** | Alles ist eine Ressource mit einer URL | `/api/patients`, `/api/doctors` |
| **HTTP-Methoden** | GET = lesen, POST = erstellen, PUT = aktualisieren, DELETE = löschen | `GET /api/patients/me/records` |
| **Zustandslos** (stateless) | Jeder Request enthält alle nötigen Informationen | JWT-Token im `Authorization`-Header |
| **JSON als Format** | Daten werden als JSON ausgetauscht | `{"email": "test@at", "password": "123"}` |

## @RestController vs. @Controller

In der Thymeleaf-Welt habt ihr `@Controller` verwendet:

```java
// Bisher mit Thymeleaf
@Controller
public class PatientController {
    @GetMapping("/patient")
    public String showPatient(Model model) {
        model.addAttribute("patient", patient);
        return "patient";  // → patient.html wird gerendert
    }
}
```

Im REST-Ansatz verwenden wir `@RestController`:

```java
// Neu mit REST API
@RestController
@RequestMapping("/api/patients")
public class PatientController {
    @GetMapping("/me")
    public ResponseEntity<?> getProfile(Authentication auth) {
        Patient p = patientRepo.findById(getCurrentPatientId(auth)).orElseThrow();
        return ResponseEntity.ok(Map.of("id", p.getId(), "email", p.getEmail(),
                "firstName", p.getFirstName(), "lastName", p.getLastName()));
    }
}
```

### Der Unterschied auf einen Blick

| | `@Controller` (Thymeleaf) | `@RestController` (REST API) |
|--|---------------------------|------------------------------|
| Rückgabe | **Template-Name** (String) | **Daten** (Objekt/JSON) |
| Annotation | `@Controller` | `@RestController` (= `@Controller` + `@ResponseBody`) |
| Rendering | Server rendert HTML | Client rendert HTML |
| Datenfluss | `Model` → Template | `ResponseEntity` → JSON |

## HTTP-Methoden und Mappings

Spring Boot bietet spezielle Annotationen für jede HTTP-Methode:

```java
@RestController
@RequestMapping("/api/patients")
public class PatientController {

    // GET /api/patients/me/records
    @GetMapping("/me/records")
    public ResponseEntity<?> getRecords(Authentication auth) { ... }

    // POST /api/patients/me/records
    @PostMapping("/me/records")
    public ResponseEntity<?> createRecord(Authentication auth,
                                          @RequestBody Map<String, Object> body) { ... }

    // PUT /api/patients/me/records/{id}
    @PutMapping("/me/records/{id}")
    public ResponseEntity<?> updateRecord(Authentication auth,
                                          @PathVariable Long id,
                                          @RequestBody Map<String, Object> body) { ... }

    // DELETE /api/patients/me/records/{id}
    @DeleteMapping("/me/records/{id}")
    public ResponseEntity<?> deleteRecord(Authentication auth,
                                          @PathVariable Long id) { ... }
}
```

### Die Annotationen im Detail

| Annotation | Zweck |
|------------|-------|
| `@GetMapping` | Nimmt **GET**-Requests entgegen (Daten lesen) |
| `@PostMapping` | Nimmt **POST**-Requests entgegen (Daten erstellen) |
| `@PutMapping` | Nimmt **PUT**-Requests entgegen (Daten aktualisieren) |
| `@DeleteMapping` | Nimmt **DELETE**-Requests entgegen (Daten löschen) |
| `@PathVariable` | Extrahiert einen Wert aus der URL: `/records/{id}` → `id` |
| `@RequestBody` | Extrahiert den **JSON-Body** und wandelt ihn in ein Java-Objekt um |
| `@RequestParam` | Extrahiert einen Query-Parameter: `?q=search` → `q` |

## JSON-Serialisierung mit Jackson

Wenn ein `@RestController` ein Java-Objekt zurückgibt, wird es automatisch von **Jackson** in JSON umgewandelt:

```java
// Java-Objekt wird zurückgegeben
return ResponseEntity.ok(Map.of(
    "token", token,
    "role", "PATIENT",
    "userId", patient.getId(),
    "name", patient.getFirstName() + " " + patient.getLastName()
));
```

Wird automatisch zu diesem JSON:

```json
{
    "token": "eyJhbGciOiJIUzI1NiJ9...",
    "role": "PATIENT",
    "userId": 1,
    "name": "Anna Schmidt"
}
```

> **`Map.of()`** ist eine Java-Standardmethode (seit Java 9) zum Erstellen von unveränderlichen Maps. Spring wandelt diese automatisch in JSON um.

## ResponseEntity – Statuscodes steuern

`ResponseEntity` erlaubt es, nicht nur den **Inhalt**, sondern auch den **HTTP-Statuscode** und **Header** zu setzen:

```java
// Erfolg (200 OK)
return ResponseEntity.ok(Map.of("message", "Record deleted"));

// Fehler (400 Bad Request)
return ResponseEntity.badRequest().body(Map.of("error", "Email already registered"));

// Nicht autorisiert (401 Unauthorized)
return ResponseEntity.status(401).body(Map.of("error", "Invalid email or password"));

// Verboten (403 Forbidden)
return ResponseEntity.status(403).body(Map.of("error", "Not your record"));
```

## Praxisbeispiele aus dem Projekt

### 1. Login-Endpoint (AuthController)

```java
@RestController
@RequestMapping("/api/auth")
public class AuthController {

    @PostMapping("/login")
    public ResponseEntity<?> login(@RequestBody Map<String, String> body) {
        String email = body.get("email");
        String password = body.get("password");

        // Suche nach Patient
        var patientOpt = patientRepo.findByEmail(email);
        if (patientOpt.isPresent()) {
            Patient patient = patientOpt.get();
            if (passwordEncoder.matches(password, patient.getPassword())) {
                String token = jwtTokenProvider.generateToken(
                    patient.getId(), patient.getEmail(), "PATIENT");
                return ResponseEntity.ok(Map.of(
                    "token", token, "role", "PATIENT",
                    "userId", patient.getId(),
                    "name", patient.getFirstName() + " " + patient.getLastName()
                ));
            }
        }
        // ... Doctor-Login analog ...

        return ResponseEntity.status(401).body(Map.of("error", "Invalid email or password"));
    }
}
```

### 2. Gesundheitsakte abrufen (PatientController)

```java
@RestController
@RequestMapping("/api/patients")
public class PatientController {

    @GetMapping("/me/records")
    public ResponseEntity<?> getRecords(Authentication auth) {
        Long patientId = getCurrentPatientId(auth);
        List<Map<String, Object>> result = recordRepo
            .findByPatientIdOrderByCreatedAtDesc(patientId)
            .stream().map(this::enrichRecord).collect(Collectors.toList());
        return ResponseEntity.ok(result);
    }
}
```

@PostMapping("/me/records")
public ResponseEntity<?> createRecord(Authentication auth,
                                       @RequestBody Map<String, Object> body) {
    String now = LocalDateTime.now().toString();
    HealthRecord r = new HealthRecord();
    r.setPatientId(getCurrentPatientId(auth));

    r.setDescription((String) body.get("description"));

}

## Zusammenfassung

- **`@RestController`** kombiniert `@Controller` und `@ResponseBody` – die Rückgabe wird direkt als JSON serialisiert
- **`@RequestBody`** wandelt den JSON-Body eines POST/PUT-Requests automatisch in ein Java-Objekt um
- **`ResponseEntity`** gibt Kontrolle über Statuscodes und Header
- **Jackson** (im `spring-boot-starter-web` enthalten) übernimmt die JSON-Serialisierung automatisch
- Die URL-Struktur folgt REST-Konventionen: Ressourcen sind plural, Hierarchien zeigen Beziehungen
