# 05.0 – TypeScript Grundlagen

## Was ist TypeScript?

TypeScript ist eine **typisierte Obermenge von JavaScript**, die von Microsoft entwickelt wurde. TypeScript-Code wird zu **normalem JavaScript** kompiliert, das jeder Browser versteht.

```
TypeScript-Code  →  TypeScript Compiler (tsc)  →  JavaScript  →  Browser
```

Der Kerngedanke: Ihr schreibt Code mit **Typ-Annotationen** und TypeScript prüft während des Schreibens, ob ihr korrekt arbeitet. Am Ende entsteht ganz normales JavaScript.

---

## Warum TypeScript?

| Problem in JavaScript | Lösung durch TypeScript |
|----------------------|------------------------|
| Variablen haben keinen Typ | **Statische Typisierung** |
| Tippfehler erst zur Laufzeit erkannt | **Fehler beim Kompilieren** erkannt |
| Keine IDE-Unterstützung | **Autovervollständigung** und Refactoring |
| Unklare Funktionsverträge | **Interfaces** und Typ-Rückgaben |

---

## Vergleich mit Java

Als Java-Kenner kommt euch vieles bekannt vor:

| Konzept | Java | TypeScript |
|---------|------|-----------|
| Typisierung | Statisch | Statisch (optional) |
| Interfaces | `interface Patient { ... }` | `interface Patient { ... }` |
| Klassen | `class Patient { ... }` | `class Patient { ... }` |
| Vererbung | `extends` / `implements` | `extends` / `implements` |
| Generics | `List<String>` | `Array<string>` |
| Enums | `enum Status { AKTIV, INAKTIV }` | `enum Status { Aktiv, Inaktiv }` |

**Wichtiger Unterschied:** TypeScript wird nicht zu **Bytecode** kompiliert (wie Java → `.class`), sondern zu **JavaScript**. Es gibt kein `.class`-File – am Ende läuft alles als JavaScript im Browser.

## Die tsconfig.json

Die Konfigurationsdatei bestimmt, wie TypeScript kompiliert:

```json
{
  "compilerOptions": {
    "target": "ES2020",
    "module": "ES2020",
    "lib": ["ES2020", "DOM", "DOM.Iterable"],
    "outDir": "../backend/src/main/resources/static/js",
    "rootDir": "ts",
    "strict": true,
    "esModuleInterop": true,
    "skipLibCheck": true,
    "forceConsistentCasingInFileNames": true,
    "resolveJsonModule": true,
    "declaration": false,
    "sourceMap": false
  },
  "include": ["ts/**/*.ts"]
}
```

| Einstellung | Bedeutung |
|-------------|-----------|
| `target: "ES2020"` | Ausgabe-Version von JavaScript (ES2020 = moderne Features) |
| `outDir` | Wohin die kompilierte `.js`-Datei geschrieben wird |
| `rootDir` | Wo die TypeScript-Quelldateien liegen (`ts/` Verzeichnis) |
| `strict: true` | **Strengste Typprüfung** – empfehlenswert! |
| `lib` | Welche Browser-APIs sind verfügbar (DOM = HTML-Elemente) |
| `include` | Welche `.ts`-Dateien kompiliert werden sollen |

## Grundlegende Typen

TypeScript kennt **primitive Typen**, die.Java-Konstrukte ähneln:

```typescript
//string - Zeichenkette
const name: string = "Anna Schmidt";

// number - Zahlen (Ganzzahlen UND Dezimalzahlen)
const age: number = 34;
const pi: number = 3.14159;

// boolean - Wahrheitswert
const isActive: boolean = true;

// any - "beliebiger Typ" (VERMEIDEN!)
const data: any = "kann alles sein";

// void - kein Rückgabewert (wie in Java)
function logMessage(msg: string): void {
    console.log(msg);
}
```

> **Hinweis:** Im Gegensatz zu Java gibt es in TypeScript keine Unterscheidung zwischen `int`, `double`, `float` etc. – es gibt nur `number`.

## Interfaces und Typ-Annotationen

Interfaces definieren die **Struktur von Objekten** – ähnlich wie in Java:

```typescript
interface Patient {
    id: number;
    firstName: string;
    lastName: string;
    email: string;
    ssn: string;
    dateOfBirth: string;
}

interface AppState {
    token: string | null;
    role: string | null;
    userId: number | null;
    name: string | null;
    currentView: string;
}
```

Im Clinical Diary-Projekt wird das `AppState`-Interface verwendet, um den **globalen Anwendungszustand** zu beschreiben:

```typescript
const state: AppState = {
    token: localStorage.getItem("token"),
    role: localStorage.getItem("role"),
    userId: parseInt(localStorage.getItem("userId") || "0"),
    name: localStorage.getItem("name"),
    currentView: "login",
};
```

Der Operator `|` definiert **Union Types** – hier: `string | null` bedeutet, dass der Wert entweder ein String oder `null` sein kann.

## Funktionen mit Typen

Funktionen in TypeScript bekommen **Typ-Annotationen** für Parameter und Rückgabewert:

```typescript
// Parameter mit Typ, Rückgabewert mit Typ
function createGreeting(firstName: string, lastName: string): string {
    return `Hallo, ${firstName} ${lastName}!`;
}

// Arrow Function
const addRecord = (records: Patient[], newRecord: Patient): Patient[] => {
    return [...records, newRecord];
};

// Async-Funktion mit Promise-Rückgabe
async function loadRecords(patientId: number): Promise<Patient[]> {
    const response = await fetch(`/api/patients/${patientId}/records`);
    return await response.json();
}
```

> **Vergleich mit Java:** In Java schreibt man `String createGreeting(String firstName, String lastName)`. Die Syntax ist fast identisch – nur das Schlüsselwort `function` fehlt bei Arrow Functions.

## Der `any`-Typ – und warum man ihn vermeiden sollte

```typescript
// SCHLECHT – any schaltet Typprüfung aus
function processData(data: any): any {
    return data.something.nested.value; // Kein Fehler beim Kompilieren!
}

// GUT – expliziter Typ
interface ApiResult {
    something: {
        nested: {
            value: string;
        };
    };
}

function processData(data: ApiResult): string {
    return data.something.nested.value; // Fehler wird erkannt, falls falsch
}
```

Im Clinical Diary-Projekt wird `any` vereinzelt verwendet, wenn die Struktur der API-Antwort nicht vollständig typisiert ist – z.B. bei `renderRecordCard(record: any, ...)`. Das ist ein **Kompromiss** zwischen strikter Typisierung und pragmatischer Entwicklung.

## Klassen (Kurzüberblick)

TypeScript-Klassen funktionieren fast identisch zu Java:

```typescript
class HealthRecord {
    id: number;
    title: string;
    category: string;

    constructor(id: number, title: string, category: string) {
        this.id = id;
        this.title = title;
        this.category = category;
    }

    getLabel(): string {
        return `[${this.category}] ${this.title}`;
    }
}
```

TypeScript unterstützt auch **Modifikatoren** wie `public`, `private`, `readonly`:

```typescript
class Patient {
    constructor(
        public readonly id: number,
        public firstName: string,
        public lastName: string,
        private _email: string
    ) {}

    get email(): string {
        return this._email;
    }
}
```

## Kompilieren mit tsc

Der **TypeScript Compiler** (`tsc`) liest die `tsconfig.json` und kompiliert alle `.ts`-Dateien zu `.js`:

```bash
# Im frontend-Verzeichnis ausführen:
cd frontend
npx tsc
```

Das Ergebnis ist eine Datei in `backend/src/main/resources/static/js/app.js` – genau diese Datei lädt das `index.html`:

```html
<script src="/js/app.js"></script>
```

---

## Zusammenfassung

| Konzept | TypeScript | Java |
|---------|-----------|------|
| Typisierung | Optional, aber empfohlen | Immer |
| Kompilierung | TS → JS (Text → Text) | Java → Bytecode |
| Ausführung | Im Browser | Auf JVM |
| Interfaces | Identische Syntax | Identische Syntax |
| Null-Werte | `string \| null` | `@Nullable` oder `Optional` |
| Modifikatoren | `public`, `private`, `readonly` | `public`, `private`, `final` |
