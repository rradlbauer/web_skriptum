# 01.1 Kommunikationsprotokolle & Request-Response-Modell

Damit Client und Server miteinander sprechen können, müssen sie eine gemeinsame **Sprache** sprechen. Diese Sprache nennt man **Protokoll**. Das wichtigste Protokoll im Web ist **HTTP** – hier geht es um das Grundprinzip der **Kommunikationsprotokolle** und um das **Request-Response-Modell**.

## Was ist ein Kommunikationsprotokoll?

Ein **Kommunikationsprotokoll** ist eine **Vereinbarung** darüber, wie Nachrichten zwischen zwei Computern ausgetauscht werden. Es legt fest:

- In welchem **Format** die Nachrichten sein müssen
- In welcher **Reihenfolge** die Partner sprechen dürfen
- Wie **Fehler** und das **Ende** einer Kommunikation erkannt werden

Ein anschaulicher Vergleich: Zwei Ärzt*innen, die in verschiedenen Sprachen arbeiten, benötigen für die Übergabe eines Patienten ebenfalls eine gemeinsame "Sprache" und ein festes Prozedere.

## HTTP – das Protokoll des Webs

**HTTP (Hypertext Transfer Protocol)** ist das Protokoll, über das Browser und Webserver kommunizieren. Es ist ein einfaches **Request-Response-Protokoll**:

```
Client                    Server
  |  -- Request   --------> |
  |  <-- Response ---------  |
```

### Die Request (Anfrage)

Eine HTTP-Request besteht aus:

- Einer **Methode** (z. B. `GET`, `POST`, `PUT`, `DELETE`)
- Der **URL** (wohin die Anfrage geht)
- **Headern** (zusätzliche Informationen, z. B. der Inhaltstyp)
- Optional einem **Body** (übertragene Daten, z. B. bei `POST`)

### Die Response (Antwort)

Eine HTTP-Response besteht aus:

- Einem **Statuscode** (z. B. `200 OK`, `404 Not Found`, `500 Internal Server Error`)
- **Headern** (z. B. der Inhaltstyp `Content-Type`)
- Der **Body** (den übertragenen Inhalt, z. B. HTML oder JSON)

## Wichtige HTTP-Methoden

| Methode | Bedeutung | Beispiel |
|---------|-----------|----------|
| `GET` | Ressource **lesen** (keine Änderung) | Patientendaten laden |
| `POST` | Neue Ressource **anlegen** (Daten im Body) | Neuen Patienten anlegen |
| `PUT` | Ressource **vollständig ersetzen** | Patientendaten aktualisieren |
| `PATCH` | Ressource **teilweise ändern** | Nur die Telefonnummer ändern |
| `DELETE` | Ressource **löschen** | Patienten löschen |

## Wichtige HTTP-Statuscodes

| Status | Bedeutung |
|--------|-----------|
| `200 OK` | Erfolgreich |
| `201 Created` | Ressource erfolgreich angelegt (bei `POST`) |
| `400 Bad Request` | Anfrage falsch formatiert |
| `401 Unauthorized` | Nicht angemeldet / nicht berechtigt |
| `404 Not Found` | Ressource nicht gefunden |
| `500 Internal Server Error` | Fehler auf dem Server |

## Das Request-Response-Modell in der Praxis

Ein Klick auf einen Link führt zu folgendem Ablauf:

1. Der Browser (Client) sendet einen `GET`-Request an die URL des Servers
2. Der Server verarbeitet die Anfrage
3. Der Server sendet eine `Response` (z. B. eine HTML-Seite mit Status `200 OK`) zurück
4. Der Browser rendert die Seite

```
GET /patients HTTP/1.1
Host: localhost:8080
```

```
HTTP/1.1 200 OK
Content-Type: application/json

[{"id":1,"name":"Anna Maier"},{"id":2,"name":"Bernd Huber"}]
```

## Zusammenfassung

### Wichtige Begriffe
- Kommunikationsprotokoll
- HTTP, Request, Response
- HTTP-Methoden: `GET`, `POST`, `PUT`, `PATCH`, `DELETE`
- Statuscodes: `200`, `201`, `400`, `404`, `500`

### Das sollst du können
- Erklären, was ein Kommunikationsprotokoll ist
- Die Bestandteile einer HTTP-Request und einer HTTP-Response nennen
- Wichtige HTTP-Methoden und Statuscodes zuordnen
- Den Ablauf einer Request-Response-Kommunikation beschreiben
