# 07.2 Spring Boot – Services, Entities & Repositories

In diesem Kapitel betrachten wir die drei weiteren Bausteine einer Spring-Boot-Anwendung: **Entity-Klassen**, **Repositories** und **Services**.

## Entity-Klassen

Eine **Entity** ist eine Java-Klasse, die eine **Tabelle der Datenbank** abbildet – das kennst du bereits aus den JPA-Kapiteln des Java-Skriptums (12.1 und 12.2).

```java
package com.clinicaldiary.entity;

import jakarta.persistence.*;

@Entity
@Table(name = "patients")
public class Patient {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Column(nullable = false)
    private String firstName;

    @Column(nullable = false)
    private String lastName;

    private String diagnosis;

    public Patient() {}

    // Getter und Setter (gekürzt)
    public Long getId() { return id; }
    public void setId(Long id) { this.id = id; }
    public String getFirstName() { return firstName; }
    public void setFirstName(String firstName) { this.firstName = firstName; }
    public String getLastName() { return lastName; }
    public void setLastName(String lastName) { this.lastName = lastName; }
    public String getDiagnosis() { return diagnosis; }
    public void setDiagnosis(String diagnosis) { this.diagnosis = diagnosis; }
}
```

| Annotation | Bedeutung |
|------------|-----------|
| `@Entity` | Klasse ist eine JPA-Entität |
| `@Table(name = "patients")` | Name der Datenbanktabelle |
| `@Id` | Primärschlüssel |
| `@GeneratedValue(strategy = GenerationType.IDENTITY)` | ID wird automatisch vergeben |
| `@Column` | Spalten-Definition (z. B. `nullable = false`) |

**Wichtig für JSON:** Der frühere Java->JSON-Mechanismus (Jackson) serialisiert Entities automatisch über die **Getter-Methoden**. Ein `Patient`-Objekt wird dadurch zu:

```json
{"id":1,"firstName":"Anna","lastName":"Maier","diagnosis":"Grippe"}
```

## Repositories

Ein **Repository** ist eine Schnittstelle, die Spring Data JPA automatisch implementiert. Für CRUD genügt eine minimale Deklaration:

```java
package com.clinicaldiary.repository;

import com.clinicaldiary.entity.Patient;
import org.springframework.data.jpa.repository.JpaRepository;

import java.util.List;

public interface PatientRepository extends JpaRepository<Patient, Long> {
    List<Patient> findByLastNameContaining(String lastName);
}
```

- `JpaRepository<Patient, Long>` bringt fertige Methoden mit: `findAll()`, `findById(id)`, `save(entity)`, `deleteById(id)`
- Zusätzliche Suchmethoden definierst du über die **Methodensignatur** – Spring erzeugt die passende Query automatisch (z. B. `findByLastNameContaining` → `LIKE '%...%'`)

## Services

Ein **Service** enthält die **Geschäftslogik** und kapselt sie vom Controller. Damit bleibt der Controller schlank und die Logik ist testbar und wiederverwendbar.

```java
package com.clinicaldiary.service;

import com.clinicaldiary.entity.Patient;
import com.clinicaldiary.repository.PatientRepository;
import org.springframework.stereotype.Service;

import java.util.List;

@Service
public class PatientService {

    private final PatientRepository patientRepo;

    public PatientService(PatientRepository patientRepo) {
        this.patientRepo = patientRepo;
    }
}
```

### Beispiel: Logik im Service

Im Service liegen Regeln, die über das reine Speichern hinausgehen – z. B. eine Plausibilitätsprüfung:

```java
public Patient createPatient(Patient patient) {
    if (patient.getFirstName() == null || patient.getFirstName().isBlank()) {
        throw new IllegalArgumentException("Vorname darf nicht leer sein");
    }
    return patientRepo.save(patient);
}
```

Der Controller ruft nur noch die Service-Methode auf:

```java
@PostMapping
public Patient createPatient(@RequestBody Patient patient) {
    return patientService.createPatient(patient);
}
```

## Zusammenspiel der Bausteine

```
Client (fetch/JSON)
      ↓ HTTP
Controller   ← @GetMapping / @PostMapping usw.
      ↓
Service      ← @Service: Geschäftslogik
      ↓
Repository   ← JpaRepository: Datenbankzugriff
      ↓
MySQL
```

## Abhängigkeitsinjektion

Controller, Service und Repository werden über den **Konstruktor** verdrahtet. Spring erzeugt die Objekte automatisch und übergibt sie (Constructor Injection):

```java
PatientController(PatientRepository patientRepo) { ... }
PatientService(PatientRepository patientRepo) { ... }
```

Du musst keine `new`-Aufrufe schreiben – das ist **Dependency Injection**.

## Zusammenfassung

### Wichtige Begriffe
- Entity: `@Entity`, `@Table`, `@Id`, `@GeneratedValue`, `@Column`
- Repository: `JpaRepository<T, Long>`, Methodensignaturen (`findBy...`)
- Service: `@Service`, Geschäftslogik
- Dependency Injection (Constructor Injection)

### Das sollst du können
- Eine Entity-Klasse modellieren
- Ein Repository für CRUD-Operationen definieren und um eigene Suchmethoden erweitern
- Einfache Geschäftslogik in einem Service unterbringen
- Die Schichten Controller–Service–Repository beschreiben
