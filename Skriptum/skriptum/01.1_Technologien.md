## Spring Boot 3.4

Spring Boot ist ein Framework, das die Entwicklung von Java-Anwendungen vereinfacht. Es liefert einen **embedded Tomcat** (Webserver direkt in der Anwendung) und **Auto-Konfiguration** – ihr müsst wenig Konfigurationscode schreiben.

Bisher habt ihr Spring Boot bereits mit Thymeleaf verwendet. Hier wird es stattdessen als **REST API** eingesetzt – der Server liefert nur **JSON-Daten**, kein HTML.

## Spring Data JPA / Hibernate

JPA (Java Persistence API) ist der Standard für Object-Relational Mapping in Java. **Hibernate** ist die populärste Implementierung. **Spring Data JPA** vereinfacht die Arbeit mit Repositories – ihr definiert Interfaces und Spring generiert die Implementierung.

```java
public interface PatientRepository extends JpaRepository<Patient, Long> {
    Optional<Patient> findByEmail(String email);
}
```

Bisher habt ihr JPA bereits verwendet – hier ändert sich daran nichts.

## H2 Database

H2 ist eine **In-Memory-Datenbank** – die Daten leben nur solange die Anwendung läuft. Das ist ideal für die **Entwicklung und Tests**, da keine externe Datenbank installiert werden muss.

```properties
# application.properties
spring.datasource.url=jdbc:h2:mem:clinicaldiary
spring.h2.console.enabled=true
```

Bisher hattet ihr vermutlich eine relationale Datenbank (z.B. PostgreSQL, MySQL). Hier verwenden wir H2 als In-Memory-Datenbank – beim Neustart der Anwendung sind alle Daten wieder weg.

## Spring Security

Spring Security ist das Standard-Framework für **Authentifizierung** (Wer bist du?) und **Autorisierung** (Was darfst du?) in Spring-Anwendungen.

Bisher hattet ihr vermutlich Session-basierte Anmeldung (Cookie + Session-ID). Hier wird **JWT** verwendet – ein alternativer, stateless Ansatz.

## JWT (JSON Web Token)

JWT ist ein **stateless Authentifizierungsmechanismus**. Statt einer Session auf dem Server wird ein **Token** erzeugt, den der Client bei jedem Request mitschickt:

```
1. Client sendet Login-Daten → Server prüft → erzeugt JWT Token
2. Client speichert Token (localStorage)
3. Bei jedem Request: Header "Authorization: Bearer <token>"
4. Server validiert Token → kennt User ohne Session
```

Ein JWT Token besteht aus drei Teilen (Base64-kodiert):

```
eyJhbGciOiJIUzI1NiJ9.eyJzdWIiOiJwYXRpZW50QGV4YW1wbGUuY29tIiwicm9sZSI6IlBBVElFTlQifQ.<signature>
```

| Teil | Inhalt |
|------|--------|
| **Header** | Algorithmus (z.B. HS256) |
| **Payload** | User-Informationen (Email, Rolle, Ablaufzeit) |
| **Signature** | Signatur zur Verifizierung |

## TypeScript

TypeScript ist **JavaScript mit Typen**. Ihr schreibt Code mit Typ-Annotationen und TypeScript kompiliert ihn zu normalem JavaScript, das der Browser versteht.

```typescript
interface Patient {
    id: number;
    firstName: string;
    lastName: string;
    email: string;
}

async function getPatient(id: number): Promise<Patient> {
    const response = await fetch(`/api/patients/${id}`);
    return await response.json();
}
```

**Vorteile gegenüber JavaScript:**
- Fehler werden **während des Schreibens** erkannt (nicht erst im Browser)
- **Autovervollständigung** in der IDE
- Bessere **Lesbarkeit** durch Typ-Annotationen

## Vanilla HTML/CSS

Für das Frontend verwenden wir **kein Framework** (kein React, Angular oder Vue). Statt dessen arbeiten wir mit reinem HTML, CSS und TypeScript. Das hilft euch, die Grundlagen zu verstehen, bevor ihr euch Frameworks widmet.

## Maven

```xml
    <artifactId>spring-boot-starter-web</artifactId>

```

## Fetch API

Die **Fetch API** ist eine native Browser-API für HTTP-Anfragen. Sie ersetzt `XMLHttpRequest` und arbeitet mit **Promises** (bzw. `async/await`).

```typescript
// GET-Anfrage
const response = await fetch('/api/patients');
const patients: Patient[] = await response.json();

// POST-Anfrage
await fetch('/api/health-records', {
    method: 'POST',
    headers: {
        'Content-Type': 'application/json',
        'Authorization': `Bearer ${token}`
    },
    body: JSON.stringify({ type: 'ILLNESS', description: 'Erkältung' })
});
```

## Vergleich: Thymeleaf-Ansatz vs. REST-API-Ansatz

| Aspekt | Thymeleaf-Ansatz | REST-API-Ansatz |
|--------|-----------------|----------------|
| **Rendering** | Serverseitig | Clientseitig |
| **HTML** | Vom Server generiert | Vom Browser generiert |
| **Kommunikation** | Seitenladen (vollständig) | AJAX/Fetch (nur Daten) |
| **Authentifizierung** | Session/Cookie | JWT Token |
| **Frontend** | Thymeleaf-Template | TypeScript SPA |
| **Entkopplung** | Gering (Server + HTML) | Hoch (Server + Client) |
| **Wiederverwendbarkeit** | Nur Web-Browser | Web, Mobile, andere Systeme |
| **Ladeverhalten** | Kompletter Seitenreload | Nur geänderte Daten werden geladen |
