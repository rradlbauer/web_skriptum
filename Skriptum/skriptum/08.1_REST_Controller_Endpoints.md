# 07.1 Spring Boot – REST-Controller & Endpoints

Ein **REST-Controller** nimmt HTTP-Anfragen entgegen und beantwortet sie mit Daten (meist als JSON). Die einzelnen erreichbaren URLs nennt man **Endpoints**.

## Der `@RestController`

Ein Controller ist eine Klasse mit der Annotation `@RestController` und `@RequestMapping` für den gemeinsamen URL-Basis-Pfad:

```java
package com.clinicaldiary.controller;

import com.clinicaldiary.entity.Patient;
import com.clinicaldiary.repository.PatientRepository;
import org.springframework.web.bind.annotation.*;

import java.util.List;

@RestController
@RequestMapping("/api/patients")
public class PatientController {

    private final PatientRepository patientRepo;

    public PatientController(PatientRepository patientRepo) {
        this.patientRepo = patientRepo;
    }
}
```

Spring erkennt die Klasse automatisch (Komponenten-Scan) und verarbeitet alle Methoden, die mit HTTP-Annotationen markiert sind.

## Mapping-Annotationen

| Annotation | HTTP-Methode | Verwendung |
|------------|--------------|------------|
| `@GetMapping` | `GET` | Daten lesen |
| `@PostMapping` | `POST` | neue Ressource anlegen |
| `@PutMapping` | `PUT` | Ressource aktualisieren |
| `@DeleteMapping` | `DELETE` | Ressource löschen |

```java
@GetMapping
public List<Patient> listPatients() {
    return patientRepo.findAll();
}

@GetMapping("/{id}")
public Patient getPatient(@PathVariable Long id) {
    return patientRepo.findById(id).orElseThrow();
}

@PostMapping
public Patient createPatient(@RequestBody Patient patient) {
    return patientRepo.save(patient);
}

@DeleteMapping("/{id}")
public void deletePatient(@PathVariable Long id) {
    patientRepo.deleteById(id);
}
```

Diese vier Methoden bilden die typischen CRUD-Operationen einer REST-API ab.

## Request-Daten übernehmen

| Annotation | Woher kommen die Daten? | Beispiel |
|------------|------------------------|----------|
| `@PathVariable` | Platzhalter im URL-Pfad | `/{id}` → `id` |
| `@RequestBody` | JSON-Body der Anfrage | das gesamte Patient-Objekt |
| `@RequestParam` | Query-Parameter in der URL | `/search?q=Maier` |

```java
@GetMapping("/search")
public List<Patient> searchPatients(@RequestParam String q) {
    return patientRepo.findByLastNameContaining(q);
}

@GetMapping("/{id}")
public Patient getPatient(@PathVariable Long id) {
    return patientRepo.findById(id).orElseThrow();
}
```

## Antworten und Statuscodes

Standardmäßig liefert Spring das zurückgegebene Objekt als **JSON** und einen passenden Statuscode (z. B. `200 OK` bei Erfolg, `201 Created` bei `@PostMapping`). Wenn du Statuscode und Antwortdetails selbst steuern willst, verwendest du `ResponseEntity`:

```java
import org.springframework.http.ResponseEntity;

@PostMapping
public ResponseEntity<Patient> createPatient(@RequestBody Patient patient) {
    Patient saved = patientRepo.save(patient);
    return ResponseEntity.status(201).body(saved);
}
```

Bei einer Suche ohne Ergebnis lieferst du z. B. `404 Not Found`:

```java
@GetMapping("/{id}")
public ResponseEntity<Patient> getPatient(@PathVariable Long id) {
    return patientRepo.findById(id)
            .map(ResponseEntity::ok)
            .orElseGet(() -> ResponseEntity.notFound().build());
}
```

## Die fertige Übersicht der Endpoints

| HTTP-Methode | URL | Bedeutung |
|--------------|-----|-----------|
| `GET` | `/api/patients` | alle Patienten lesen |
| `GET` | `/api/patients/{id}` | einen Patienten lesen |
| `GET` | `/api/patients/search?q=...` | Patienten suchen |
| `POST` | `/api/patients` | Patienten anlegen (Body: JSON) |
| `PUT` | `/api/patients/{id}` | Patienten aktualisieren |
| `DELETE` | `/api/patients/{id}` | Patienten löschen |

Genau diese Endpoints ruft das TypeScript-Frontend mit der `fetch`-API aus Kapitel 07.4 auf.

## Zusammenfassung

### Wichtige Begriffe
- `@RestController`, `@RequestMapping`
- `@GetMapping`, `@PostMapping`, `@PutMapping`, `@DeleteMapping`
- `@PathVariable`, `@RequestBody`, `@RequestParam`
- `ResponseEntity`, Statuscodes (`200`, `201`, `404`)
- CRUD-Operationen, Endpoints

### Das sollst du können
- Einen REST-Controller mit CRUD-Endpoints schreiben
- Request-Daten über `@PathVariable`, `@RequestBody`, `@RequestParam` übernehmen
- Antworten mit `ResponseEntity` steuern
