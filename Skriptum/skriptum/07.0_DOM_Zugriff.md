# 07.0 TypeScript – Zugriff auf HTML-Elemente (DOM)

Damit TypeScript eine Webseite verändern kann, muss es – genau wie JavaScript – auf die HTML-Elemente **zugreifen**. Das geschieht über das **DOM**. In diesem Kapitel siehst du dieselben Techniken wie in den JavaScript-Kapiteln, aber **typisiert**.

> Voraussetzung: Du kennst die JavaScript-Grundlagen aus Kapitel 05.x. Hier liegt der Fokus auf den TypeScript-spezifischen Teilen: Typen, `null`-Behandlung und Typ-Assertions (`as`).

## Was ist das DOM?

Das **DOM (Document Object Model)** ist die **Baum-Struktur**, in der der Browser eine HTML-Seite darstellt. Jedes HTML-Element wird zu einem **Knoten**, auf den TypeScript zugreifen kann.

```ts
const info = document.getElementById("info");
```

Damit kann TypeScript Elemente **suchen**, **lesen** und **verändern** – im Browser-Build, der aus den `.ts`-Dateien erzeugt wird.

## Elemente suchen – und die wichtigen Typen

Die Such-Methoden sind dieselben wie in JavaScript. TypeScript kennt jedoch ihre **Ergebnistypen**:

| Methode | Ergebnis-Typ | Hinweis |
|---------|--------------|---------|
| `document.getElementById("id")` | `HTMLElement \| null` | kann nicht gefunden werden |
| `document.querySelector(".karte")` | `Element \| null` | erstes passendes Element |
| `document.querySelectorAll(".karte")` | `NodeListOf<Element>` | alle passenden Elemente |

```ts
const title = document.getElementById("title");
const ersteKarte = document.querySelector(".karte");
const alleKarten = document.querySelectorAll(".karte");
```

> **Der `null`-Fall ist der wichtigste TypeScript-Unterschied:** `getElementById` liefert `HTMLElement | null`. TypeScript zwingt dich, den Fall "Element nicht gefunden" zu bedenken.

### Umgang mit `null`

```ts
const title = document.getElementById("title");

// Variante 1: if-Prüfung
if (title !== null) {
    title.textContent = "Neuer Text";
}

// Variante 2: Non-Null-Assertion "!" (wenn du sicher bist)
const info = document.getElementById("info")!;
info.textContent = "Patient wurde ausgewählt";
```

`!` sagt dem Compiler: "dieser Wert ist nicht `null`". Verwende `!` nur, wenn du sicher bist, dass das Element existiert – sonst besser die `if`-Prüfung.

### Konkrete Typen mit `as`

`getElementById` liefert allgemein `HTMLElement`. Ein `input`-Feld ist aber spezieller (`HTMLInputElement`). Mit **`as`** sagst du TypeScript, welcher konkrete Typ gemeint ist:

```ts
const nameInput = document.getElementById("name") as HTMLInputElement;
console.log(nameInput.value);
```

Weitere konkrete Typen:

| Typ | Element |
|-----|---------|
| `HTMLInputElement` | `<input>` |
| `HTMLSelectElement` | `<select>` |
| `HTMLTextAreaElement` | `<textarea>` |
| `HTMLTableElement` | `<table>` |
| `HTMLButtonElement` | `<button>` |

## Elemente lesen (Inhalt ändern)

### `textContent` – Inhalt als Text

```ts
const info = document.getElementById("info")!;
info.textContent = "Neuer Text";   // schreiben
const inhalt: string = info.textContent ?? "";
```

### `innerHTML` – Inhalt als HTML

```ts
info.innerHTML = "<strong>Wichtiger</strong> Hinweis";
```

> Vorsicht: `innerHTML` interpretiert HTML. Für **Benutzereingaben** ist `textContent` sicherer (XSS, siehe unten).

## Elemente gestalten (CSS über TypeScript)

```ts
const karte = document.querySelector(".karte")!;
karte.style.backgroundColor = "#f0f0f0";
karte.style.border = "1px solid #ccc";
karte.style.color = "blue";
```

CSS-Eigenschaften werden in **camelCase** geschrieben: `background-color` → `backgroundColor`.

Mit `classList` fügst du Klassen hinzu/entfernst:

```ts
karte.classList.add("wichtig");
karte.classList.remove("wichtig");
karte.classList.toggle("aktiv");
```

## Events: auf Aktionen reagieren

```ts
const button = document.getElementById("aendern")!;

button.addEventListener("click", (event: MouseEvent) => {
    const info = document.getElementById("info")!;
    info.textContent = "Patient wurde ausgewählt";
    console.log(`Klick auf ${button.id}`);
});
```

TypeScript kennt die Event-Typen: `MouseEvent` für `click`, `Event` für `submit`, `InputEvent`/`Event` für `input`.

## Sicherheit: textContent statt innerHTML

`innerHTML` setzt HTML um. Setzt du dort **unverifizierte** Eingaben ein (z. B. Namen aus einer API), kann eingeschleuster Code ausgeführt werden (**XSS** – Cross-Site Scripting). Verwende deshalb für Benutzerdaten immer `textContent`.

## Arbeiten mit dem Ergebnis (Beispiel)

```ts
function setDiagnosis(diagnosis: string): void {
    const output = document.getElementById("diagnosis")!;
    output.textContent = diagnosis;
}

const feld = document.getElementById("diagnosisInput") as HTMLInputElement;
const button = document.getElementById("uebertragen")!;

button.addEventListener("click", () => {
    setDiagnosis(feld.value);
});
```

## Zusammenfassung

### Wichtige Begriffe
- DOM, `HTMLElement`, `HTMLInputElement`, ...
- `Element | null`, Non-Null-Assertion `!`
- Typ-Assertion `as`
- `textContent`, `innerHTML` (XSS-Gefahr)
- `style`, `classList`, `addEventListener`, `MouseEvent`

### Das sollst du können
- HTML-Elemente mit TypeScript suchen und ihre Typen benennen
- Den `null`-Fall von `getElementById` korrekt behandeln
- Konkrete Elementtypen mit `as` verwenden
- Inhalt lesen/schreiben und Elemente über `style`/`classList` gestalten
