# 09.1 Single Page Application (SPA)

Eine **Single Page Application (SPA)** ist eine Web-Applikation, die aus **einer einzigen HTML-Seite** besteht (Kapitel 02.1). Alle Ansichten werden **client-seitig** in TypeScript umgeschaltet, Daten kommen als JSON von der REST-API.

## Grundprinzip

- Der Browser lädt **einmal** die `index.html` (mit allen CSS- und TypeScript-/JavaScript-Dateien)
- **Ansichten** (z. B. "Patientenliste", "Patient anlegen", "Details") sind Bereiche im HTML
- TypeScript blendet die Ansichten ein/aus und **lädt bei Bedarf Daten** vom Server (fetch)
- Es gibt **keine** vollständigen Seitenwechsel mehr

```
index.html
  ├── <div id="view-list">    Ansicht: Patientenliste
  ├── <div id="view-form">    Ansicht: Patient anlegen
  └── <script src="app.ts">   (via Vite compiliert) steuert die Ansichten
```

> **Hinweis:** Im Vite-Projekt ldts du die TypeScript-Datei in der `index.html` als `src="src/app.ts"` (oder `src="src/main.ts"`). Vite kompiliert und liefert sie.

## Die Grundstruktur der index.html

```html
<!DOCTYPE html>
<html lang="de">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <link rel="stylesheet" href="styles.css">
    <title>Patientenverwaltung</title>
</head>
<body>
    <nav id="mainNav">
        <button data-view="list">Patientenliste</button>
        <button data-view="form">Patient anlegen</button>
    </nav>

    <main>
        <section id="view-list" class="view">
            <h2>Patienten</h2>
            <table id="patientTable">
                <tr><th>Name</th><th>Diagnose</th></tr>
            </table>
        </section>

        <section id="view-form" class="view hidden">
            <h2>Patient anlegen</h2>
            <form id="patientForm">
                <label for="firstName">Vorname:</label>
                <input type="text" id="firstName" name="firstName">
                <label for="lastName">Nachname:</label>
                <input type="text" id="lastName" name="lastName">
                <label for="diagnosis">Diagnose:</label>
                <input type="text" id="diagnosis" name="diagnosis">
                <button type="submit">Speichern</button>
            </form>
        </section>
    </main>

    <script type="module" src="src/main.ts"></script>
</body>
</html>
```

## Interface für die API-Antwort

```ts
interface Patient {
    id: number;
    firstName: string;
    lastName: string;
    diagnosis: string;
}
```

## Ansichten umschalten

```css
.hidden {
    display: none;
}
```

```ts
function showView(viewId: string): void {
    const views = document.querySelectorAll(".view");
    for (let view of views) {
        (view as HTMLElement).classList.toggle("hidden", view.id !== viewId);
    }
}

document.getElementById("mainNav")!
    .addEventListener("click", (event: MouseEvent) => {
    const button = (event.target as HTMLElement).closest("button");
    if (button) {
        const viewId = button.dataset.view;
        if (viewId) {
            showView(viewId);
        }
    }
});
```

Beim Start zeigst du die Standard-Ansicht:

```ts
showView("list");
```

## SPA-Navigation: Daten werden bei jedem Wechsel geladen

Jede Ansicht kann eigene Lade-Funktionen haben. Beim Wechsel auf die Liste werden die Daten neu geladen:

```ts
function showView(viewId: string): void {
    const views = document.querySelectorAll(".view");
    for (let view of views) {
        (view as HTMLElement).classList.toggle("hidden", view.id !== viewId);
    }

    if (viewId === "list") {
        loadPatients();
    }
}
```

Der Ablauf einer SPA-Interaktion:

```
User klickt "Patientenliste"
   → showView("list")
   → loadPatients(): GET /api/patients
   → Tabelle wird im Browser gefüllt (ohne Seitenwechsel)
```

## SPA + Spring Boot Backend

Die SPA wird **statisch ausgeliefert** (HTML, CSS, TypeScript/JavaScript) und spricht über die **REST-API** mit dem Backend:

```
Browser (index.html, app.ts)
   ↕ fetch (JSON)
Spring Boot (RestController, Port 8080)
   ↕ JPA
MySQL
```

Der Spring-Boot-Teil ist derselbe wie in Kapitel 09.0 – die SPA ist nur ein **anderes Frontend** (Client-side Rendering statt Server-side Rendering mit Thymeleaf).

## Beispiel: Patientenliste in einer SPA

```ts
async function loadPatients(): Promise<void> {
    const response = await fetch("http://localhost:8080/api/patients");
    const patients = await response.json() as Patient[];

    const table = document.getElementById("patientTable") as HTMLTableElement;
    const rows = table.querySelectorAll("tr");
    for (let i = 1; i < rows.length; i++) {
        rows[i].remove();
    }

    for (let patient of patients) {
        const row: HTMLTableRowElement = document.createElement("tr");

        const nameCell: HTMLTableCellElement = document.createElement("td");
        nameCell.textContent = `${patient.firstName} ${patient.lastName}`;

        const diagnosisCell: HTMLTableCellElement = document.createElement("td");
        diagnosisCell.textContent = patient.diagnosis;

        row.appendChild(nameCell);
        row.appendChild(diagnosisCell);
        table.appendChild(row);
    }
}

showView("list");
```

## Vorteile und Nachteile einer SPA

| Vorteile | Nachteile |
|----------|-----------|
| schnelle Bedienung ohne Seitenwechsel | mehr TypeScript/JavaScript-Komplexität |
| nur ein HTML-Dokument | SEO schwieriger |
| Backend nur als API (wiederverwendbar) | erstes Laden etwas schwerer |
| flüssige Zustandswechsel | Zustandshaltung im Client |

## Zusammenfassung

### Wichtige Begriffe
- SPA, Client-side Rendering
- eine `index.html`, `hidden`-Klassen, `data-view`
- `showView(viewId)`, `dataset`, `closest`
- Interface `Patient`, `as Patient[]`
- REST-API als Backend der SPA

### Das sollst du können
- Ansichten einer SPA aus mehreren Bereichen desselben HTML-Dokuments umschalten
- Beim Ansichtswechsel Daten per fetch nachladen und typisieren
- Das Zusammenspiel von SPA (TypeScript-Frontend) und Spring Boot (REST-API) beschreiben
