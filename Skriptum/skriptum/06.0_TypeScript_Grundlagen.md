# 06.0 TypeScript – Grundlagen & Vorteile

**TypeScript** ist eine **Erweiterung (Superset)** von JavaScript: Jedes JavaScript-Programm ist auch gültiges TypeScript. TypeScript fügt JavaScript ein **Typsystem** hinzu und wird durch einen Compiler in **normales JavaScript** übersetzt, das im Browser ausgeführt wird.

Dieses Kapitel baut direkt auf Kapitel 05.x auf: Du kennst die JavaScript-Grundlagen – jetzt lernst du, wie man statt JavaScript **TypeScript** verwendet.

## Warum TypeScript?

JavaScript ist **dynamisch typisiert**: Der Typ einer Variable ergibt sich erst zur Laufzeit. Das hat Vorteile (flexibel), aber auch Nachteile – Tippfehler und falsche Typen werden erst beim Ausführen sichtbar.

TypeScript bringt **statische Typen** ein. Der Compiler prüft den Code **vor der Ausführung** und findet viele Fehler schon, bevor das Programm läuft.

Ein Beispiel – in JavaScript:

```js
function greetPatient(name) {
    return "Guten Tag, " + name;
}

greetPatient(42);   // kein Fehler beim Schreiben, aber logisch falsch
```

In TypeScript:

```ts
function greetPatient(name: string): string {
    return "Guten Tag, " + name;
}

greetPatient(42);   // Compilerfehler: number ist nicht string
```

## Vorteile von TypeScript

| Vorteil | Wirkung |
|---------|---------|
| **Statische Typen** | Falsche Typen werden schon beim Compilieren erkannt |
| **Bessere IDE-Unterstützung** | Auto-Vervollständigung, Refactoring, Navigation im Editor |
| **Frühere Fehlererkennung** | viele Bugs werden vor dem Ausführen gefunden |
| **Bessere Lesbarkeit** | Typen dienen als "Dokumentation" des Codes |
| **Interfaces & Typ-Aliase** | Datensätze (z. B. Patienten) sind klar beschrieben |
| **Selbstdokumentierende Schnittstellen** | z. B. JSON-Antworten einer REST-API |

TypeScript löst also viele Probleme, bevor sie auftreten – besonders bei **größeren** Web-Applikationen, bei denen viele Entwickler*innen zusammenarbeiten.

## Variablen mit Typen

Die Grundkonzepte aus Kapitel 05.0 bleiben gleich, zusätzlich schreibst du Typen mit `:` hinter den Namen:

```ts
let name: string = "Anna Maier";
const age: number = 42;
let isInsured: boolean = true;

let room: number | null = 102;   // Union-Typ: number ODER null
```

| Typ | Beispiel |
|-----|----------|
| `string` | `"Grippe"` |
| `number` | `36.6`, `42` |
| `boolean` | `true` |
| `number[]` | `[1, 2, 3]` (Array von Zahlen) |
| `string[]` | `["Anna", "Bernd"]` |
| `any` | beliebiger Typ (vermeiden!) |
| `string \| null` | Union-Typ |

> Typen können oft **abgeleitet** werden (Type Inference): `let bmi = 22.86;` hat automatisch den Typ `number`. Du musst nicht überall einen Typ schreiben, aber bei Funktionen und Schnittstellen lohnt es sich.

## Funktionen mit Typen

```ts
function calculateBmi(weightKg: number, heightM: number): number {
    return weightKg / (heightM * heightM);
}

const bmi: number = calculateBmi(70, 1.75);
```

- Parameter-Typen: `(weightKg: number, heightM: number)`
- Rückgabetyp: `: number` nach der Parameterliste

### Verzweigungen und Schleifen bleiben gleich

`if`/`else`, `for`, `for...of` und `while` aus Kapitel 05.1 funktionieren in TypeScript identisch – mit Typen auf den Variablen:

```ts
function classifyTemperature(temp: number): string {
    if (temp >= 39) return "hohes Fieber";
    if (temp >= 38) return "Fieber";
    if (temp >= 37) return "leicht erhöht";
    return "normal";
}

const readings: number[] = [36.1, 38.8, 39.5];
for (let reading of readings) {
    console.log(`${reading}: ${classifyTemperature(reading)}`);
}
```

## Arrays mit Typen

```ts
const patients: string[] = ["Anna Maier", "Bernd Huber"];
const ages: number[] = [42, 55];

patients.push("Eva Wagner");
console.log(patients.join(", "));
```

Arbeiten mit `map`/`filter` funktioniert wie in JavaScript (Kapitel 05.1), die Typen werden automatisch mitgenommen:

```ts
const longNames: string[] = patients.filter(p => p.length > 10);
```

## Objekte & Interfaces

Das wichtigste TypeScript-Feature für Web-Applikationen: Du beschreibst die **Form** eines Objekts mit einem **Interface**. Das passt perfekt zu den Datenstrukturen aus Kapitel 05.2 (Objekte und JSON).

```ts
interface Patient {
    id: number;
    firstName: string;
    lastName: string;
    diagnosis: string;
}
```

Damit ist die Struktur eines Patienten **festgelegt**. Der Compiler prüft, dass alle Objekte dieser Form folgen:

```ts
const patient: Patient = {
    id: 1,
    firstName: "Anna",
    lastName: "Maier",
    diagnosis: "Grippe"
};

function printPatient(p: Patient): void {
    console.log(`${p.firstName} ${p.lastName}: ${p.diagnosis}`);
}

printPatient(patient);
```

Fehler werden sofort erkannt – z. B. ein Tippfehler oder eine fehlende Eigenschaft:

```ts
const falsch: Patient = {
    id: 2,
    firstName: "Bernd",
    lastName: "Huber"
    // Fehler: diagnosis fehlt
};
```

### Optionale und Arrays von Interfaces

```ts
interface HealthRecord {
    title: string;
    description: string;
    severity?: string;      // optional
}

const records: HealthRecord[] = [
    { title: "Blutbild", description: "unauffällig" },
    { title: "EKG", description: "rhythmusstörung", severity: "mittel" }
];
```

Das Interface `Patient` beschreibt genau die JSON-Antwort, die du später von der Spring-Boot-REST-API bekommst (Kapitel 07.4).

## TypeScript in den Browser bringen

Der Browser kann **kein TypeScript** ausführen – nur JavaScript. Deshalb wird TypeScript **compiliert** (übersetzt):

```
TypeScript-Datei (.ts)  --tsc-->  JavaScript-Datei (.js)  --Browser-->  Ausführung
```

Welche Werkzeuge das übernehmen (Compiler `tsc`, `tsconfig.json`, Build-Tools wie Vite) und wie du TypeScript in deine Entwicklungsumgebung integrierst und debuggst, lernst du in Kapitel 06.1.

## Zusammenfassung

### Wichtige Begriffe
- TypeScript (Superset von JavaScript), Compiler
- Statische Typen, Typ-Inferenz, Union-Typen
- `string`, `number`, `boolean`, `string[]`, `any`
- Parameter- und Rückgabetypen (`: type`)
- Interface, optionale Eigenschaften (`?`)

### Das sollst du können
- Vorteile von TypeScript gegenüber JavaScript erklären
- Variablen, Funktionen und Arrays mit Typen versehen
- Ein Interface definieren und für Objekte verwenden
- Erklären, warum TypeScript zu JavaScript compiliert werden muss
