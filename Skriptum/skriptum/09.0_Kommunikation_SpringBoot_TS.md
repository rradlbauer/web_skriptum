# 09.0 Kommunikation Spring Boot – TypeScript

In diesem Kapitel fügen wir alles zusammen: Eine **Spring-Boot-REST-API**, die Daten als JSON liefert, und ein **TypeScript-Frontend**, das diese Daten lädt, anzeigt und neue Daten an den Server sendet. Wir betrachten auch **1:n-Beziehungen** zwischen Entitäten.

## Ausgangssituation

Backend (Spring Boot, Port `8080`):

| Endpoint | Bedeutung |
|----------|-----------|
| `GET /api/patients` | alle Patienten als JSON |
| `POST /api/patients` | neuen Patienten anlegen |
| `GET /api/patients/{id}/health-records` | alle Gesundheitseinträge eines Patienten |

Frontend (TypeScript/Vite): Eine Seite, die die Patientenliste anzeigt und Formulardaten an den Server sendet.

## Interface definieren

Das erste und wichtigste Stück: Die **JSON-Antwort** wird als TypeScript-Interface beschrieben:

```ts
interface Patient {
    id: number;
    firstName: string;
    lastName: string;
    diagnosis: string;
}
```

## Array von Entities laden und in einer HTML-Tabelle anzeigen

TypeScript ruft die API auf, erhält ein **Array von Entities** (als JSON) und baut damit eine Tabelle – **typisiert**.

### Backend: Controller

```java
@RestController
@RequestMapping("/api/patients")
public class PatientController {

    private final PatientRepository patientRepo;

    public PatientController(PatientRepository patientRepo) {
        this.patientRepo = patientRepo;
    }

    @GetMapping
    public List<Patient> listPatients() {
        return patientRepo.findAll();
    }
}
```

### Frontend: laden, typisieren und anzeigen

```ts
async function loadPatients(): Promise<void> {
    try {
        const response = await fetch("http://localhost:8080/api/patients");
        if (!response.ok) {
            throw new Error("HTTP-Fehler " + response.status);
        }

        const patients = await response.json() as Patient[];

        const table = document.getElementById("patientTable") as HTMLTableElement;
        clearTableRows(table);

        for (let patient of patients) {
            const row: HTMLTableRowElement = document.createElement("tr");

            const nameCell: HTMLTableCellElement = document.createElement("td");
            nameCell.textContent = `${patient.firstName} ${patient.lastName}`;

            const diagnosisCell: HTMLTableCellElement = document.createElement("td");
            diagnosisCell.textContent = patient.diagnosis;

            row.appendChild(nameCell);
            row.appendChild(diagnosisCell);
            table.appendChild(row);
        }
    } catch (error) {
        console.log("Laden fehlgeschlagen: " + error);
    }
}
```

TypeScript prüft, dass du auf die richtigen Felder zugreifst (`patient.firstName`, `patient.diagnosis` – keine Tippfehler).

## Formulardaten auslesen und als neue Entity speichern

Der umgekehrte Weg: Der Benutzer füllt ein Formular aus, TypeScript sammelt die Werte in einem Interface-Objekt und sendet es per `POST` an den Server.

### Backend: POST-Endpoint

```java
@PostMapping
public ResponseEntity<Patient> createPatient(@RequestBody Patient patient) {
    Patient saved = patientRepo.save(patient);
    return ResponseEntity.status(201).body(saved);
}
```

### Frontend: Formular → POST

```ts
interface PatientFormData {
    firstName: string;
    lastName: string;
    diagnosis: string;
}

document.getElementById("patientForm")!
    .addEventListener("submit", async (event: Event) => {
    event.preventDefault();

    const patient: PatientFormData = {
        firstName: (document.getElementById("firstName") as HTMLInputElement).value,
        lastName: (document.getElementById("lastName") as HTMLInputElement).value,
        diagnosis: (document.getElementById("diagnosis") as HTMLInputElement).value
    };

    const response = await fetch("http://localhost:8080/api/patients", {
        method: "POST",
        headers: { "Content-Type": "application/json" },
        body: JSON.stringify(patient)
    });

    if (response.ok) {
        alert("Patient wurde gespeichert");
        loadPatients();   // Tabelle aktualisieren
    } else {
        alert("Speichern fehlgeschlagen");
    }
});
```

Der **JavaScript-Objektname** (`patient.firstName`) muss zu den **Getter-Namen / Feldnamen der Entity** passen, damit Jackson das JSON korrekt einliest. TypeScript prüft die Feldnamen bereits beim Übersetzen.

## 1:n-Beziehungen

Ein Patient kann **viele** Gesundheitseinträge (HealthRecords) haben – eine **1:n-Beziehung**.

### Backend: Entities

```java
// HealthRecord.java
@Entity
@Table(name = "health_records")
public class HealthRecord {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    private String title;
    private String description;

    @ManyToOne
    @JsonIgnore
    @JoinColumn(name = "patient_id")
    private Patient patient;

    // Getter/Setter ...
}
```

```java
// Patient.java (Ausschnitt)
@OneToMany(mappedBy = "patient")
private List<HealthRecord> healthRecords = new ArrayList<>();
```

| Annotation | Bedeutung |
|------------|-----------|
| `@ManyToOne` + `@JoinColumn` | die n-Seite hat einen Fremdschlüssel `patient_id` |
| `@OneToMany(mappedBy = "patient")` | die 1-Seite führt die Sammlung |
| `@JsonIgnore` | verhindert Endlos-JSON auf der n-Seite |

### Backend: Endpoint für die Unter-Ressource

```java
@GetMapping("/{id}/health-records")
public List<HealthRecord> getHealthRecords(@PathVariable Long id) {
    return recordRepo.findByPatientId(id);
}
```

### Frontend: Einträge mit TypeScript laden

```ts
interface HealthRecord {
    id: number;
    title: string;
    description: string;
    severity?: string;
}

async function loadHealthRecords(patientId: number): Promise<HealthRecord[]> {
    const response = await fetch(
        `http://localhost:8080/api/patients/${patientId}/health-records`
    );
    if (!response.ok) {
        throw new Error("HTTP-Fehler " + response.status);
    }
    return await response.json() as HealthRecord[];
}
```

```ts
const records = await loadHealthRecords(1);

const list = document.getElementById("recordList") as HTMLUListElement;
for (let record of records) {
    const li: HTMLLIElement = document.createElement("li");
    li.textContent = `${record.title}: ${record.description}`;
    list.appendChild(li);
}
```

## CORS

Wenn du das Frontend mit **Vite** (Port `5173`) und das Backend auf Port `8080` betreibst, blockiert der Browser die Anfrage (Same-Origin-Policy, Kapitel 07.4). Der Server muss die fremde Herkunft erlauben:

```java
@RestController
@RequestMapping("/api/patients")
@CrossOrigin(origins = "http://localhost:5173")
public class PatientController { ... }
```

Oder eine globale Konfiguration:

```java
@Configuration
public class CorsConfig implements WebMvcConfigurer {
    @Override
    public void addCorsMappings(CorsRegistry registry) {
        registry.addMapping("/api/**").allowedOrigins("http://localhost:5173");
    }
}
```

> **Hinweis:** In Produktion sollte `allowedOrigins` nur die erlaubte Herkunft enthalten – nicht `"*"`.

## Zusammenfassung

### Wichtige Begriffe
- REST-API ↔ TypeScript (`fetch`), Interface `Patient`
- `response.json() as Patient[]`, `as Patient`
- Array von Entities → HTML-Tabelle (typisiert)
- Formulardaten → `POST` → neue Entity
- 1:n-Beziehung: `@OneToMany`, `@ManyToOne`, `@JsonIgnore`
- CORS (`@CrossOrigin`)

### Das sollst du können
- Entities mit `fetch` laden und als typisiertes Array in einer Tabelle anzeigen
- Formulardaten als JSON an den Server senden (POST)
- Eine 1:n-Beziehung in den Entities modellieren und als Unter-Ressource ausliefern
- CORS verstehen und konfigurieren
