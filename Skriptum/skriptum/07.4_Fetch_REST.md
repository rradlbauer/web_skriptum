# 07.4 TypeScript – fetch-API & REST

Mit der **fetch-API** kannst du Daten von einem Server **laden** und an einen Server **senden** – typischerweise eine **REST-API**, die Daten als JSON liefert. Das ist die Brücke zwischen Browser (Client) und Backend (Spring Boot). In TypeScript wird die **Antwort der API mit einem Interface typisiert** – das ist der große Vorteil gegenüber JavaScript.

## Was ist REST?

**REST (Representational State Transfer)** ist ein Architektur-Stil für HTTP-Schnittstellen (Web-Services, Kapitel 02.0). REST-APIs:

- bilden **Ressourcen** (z. B. `patients`) auf **URLs** ab
- verwenden die **HTTP-Methoden** (`GET`, `POST`, `PUT`, `DELETE`) aus Kapitel 01.1
- liefern Daten meist als **JSON**
- sind **zustandslos** (jede Anfrage ist eigenständig)

Beispiel-Endpoints einer Patienten-API:

| Methode | URL | Bedeutung |
|---------|-----|-----------|
| `GET` | `/api/patients` | alle Patienten |
| `GET` | `/api/patients/3` | ein Patient (id=3) |
| `POST` | `/api/patients` | neuen Patienten anlegen |
| `PUT` | `/api/patients/3` | Patienten 3 aktualisieren |
| `DELETE` | `/api/patients/3` | Patienten 3 löschen |

## Das Interface zur API-Antwort

Der Kern von TypeScript bei fetch: Du definierst ein **Interface**, das die JSON-Struktur der API beschreibt, und typisierst das Ergebnis von `response.json()` damit:

```ts
interface Patient {
    id: number;
    firstName: string;
    lastName: string;
    diagnosis: string;
}
```

## fetch – Daten lesen (GET)

`fetch(url)` schickt standardmäßig eine `GET`-Anfrage und liefert eine **Promise**. Mit `await` wartest du auf das Ergebnis; die zweite `await`-Zeile wandelt die Antwort in JSON um:

```ts
async function loadPatients(): Promise<void> {
    const response = await fetch("http://localhost:8080/api/patients");
    const patients = await response.json() as Patient[];
    console.log(patients);
}
```

- `response.json()` liefert `any` → mit `as Patient[]` sagst du TypeScript, dass ein **Array von Patienten** kommt
- `async function ... : Promise<void>` – eine `async`-Funktion liefert immer eine Promise; hier gibt es keinen Rückgabewert (`void`)

> **Hinweis:** Vergiss die `async`-Funktion nicht – `await` darf nur innerhalb einer `async`-Funktion verwendet werden.

## Daten in der Praxis anzeigen

Du kombinierst `fetch` mit den DOM-Techniken aus Kapitel 07.2:

```ts
async function loadPatients(): Promise<void> {
    const response = await fetch("http://localhost:8080/api/patients");
    const patients = await response.json() as Patient[];

    const table = document.getElementById("patientTable") as HTMLTableElement;

    for (let patient of patients) {
        const row: HTMLTableRowElement = document.createElement("tr");

        const nameCell: HTMLTableCellElement = document.createElement("td");
        nameCell.textContent = `${patient.firstName} ${patient.lastName}`;
        row.appendChild(nameCell);

        const diagnosisCell: HTMLTableCellElement = document.createElement("td");
        diagnosisCell.textContent = patient.diagnosis;
        row.appendChild(diagnosisCell);

        table.appendChild(row);
    }
}
```

TypeScript prüft jetzt, dass du wirklich auf gültige Felder zugreifst (`patient.firstName` statt eines Tippfehlers).

## Rückgabetyp mit Promise nutzen

Statt nur `void` kannst du die Patienten zurückgeben – so wird die Funktion wiederverwendbar:

```ts
async function fetchPatients(): Promise<Patient[]> {
    const response = await fetch("http://localhost:8080/api/patients");
    if (!response.ok) {
        throw new Error(`HTTP-Fehler ${response.status}`);
    }
    return await response.json() as Patient[];
}
```

Die Typ-Annotation `Promise<Patient[]>` macht den Rückgabetyp explizit.

## Fehlerbehandlung

```ts
async function loadPatients(): Promise<void> {
    try {
        const patients: Patient[] = await fetchPatients();

        for (let patient of patients) {
            console.log(patient.firstName);
        }
    } catch (error) {
        console.log("Laden fehlgeschlagen: " + error);
    }
}
```

## Daten senden (POST)

```ts
async function createPatient(patient: Patient): Promise<void> {
    const response = await fetch("http://localhost:8080/api/patients", {
        method: "POST",
        headers: {
            "Content-Type": "application/json"
        },
        body: JSON.stringify(patient)
    });

    if (response.ok) {
        console.log("Patient angelegt");
    }
}

const newPatient: Patient = {
    id: 0,
    firstName: "Eva",
    lastName: "Wagner",
    diagnosis: "Asthma"
};
createPatient(newPatient);
```

Der **Body** wird mit `JSON.stringify(patient)` in JSON-Text umgewandelt – das funktioniert in TypeScript genauso wie in JavaScript (Kapitel 05.2).

## PUT und DELETE

```ts
// Aktualisieren
async function updatePatient(patient: Patient): Promise<void> {
    await fetch(`http://localhost:8080/api/patients/${patient.id}`, {
        method: "PUT",
        headers: { "Content-Type": "application/json" },
        body: JSON.stringify(patient)
    });
}

// Löschen
async function deletePatient(id: number): Promise<void> {
    await fetch(`http://localhost:8080/api/patients/${id}`, {
        method: "DELETE"
    });
}
```

Mit dem Template Literal `${patient.id}` baust du die URL dynamisch zusammen.

## CORS und Same-Origin-Policy

Browser schützen sich per **Same-Origin-Policy**: Ein Skript darf standardmäßig nur Ressourcen derselben **Herkunft** (Protokoll + Host + Port) laden. Wenn du während der Entwicklung mit einer eigenen Spring-Boot-API (Port `8080`) und einer eigens gestarteten HTML-Seite (Vite, Port `5173`) arbeitest, sind die Herkünfte unterschiedlich – das nennt man **Cross-Origin**. Der Server muss dann `CORS` erlauben (in Spring Boot über `@CrossOrigin` bzw. eine CORS-Konfiguration). Details dazu in Kapitel 09.0.

## Zusammenfassung

### Wichtige Begriffe
- REST, Ressource, HTTP-Methoden
- `fetch(url)`, `response.json() as Patient[]`
- `Promise<Patient[]>`, `async` / `await`
- Interfaces für API-Antworten (Typ-Sicherheit)
- `POST`/`PUT`/`DELETE` mit `body`, `try/catch`, CORS

### Das sollst du können
- Mit `fetch` + `await` Daten von einer REST-API laden und **typisieren**
- Geladene Daten in einer Tabelle anzeigen
- Per `POST`/`PUT`/`DELETE` Daten an den Server senden
- Fehler mit `try/catch` behandeln
