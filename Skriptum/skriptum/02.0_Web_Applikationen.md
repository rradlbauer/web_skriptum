# 02.0 Web-Applikationen – Grundlagen

Eine **Web-Applikation** ist ein Programm, das über den Browser genutzt wird und über das Internet/Netzwerk erreichbar ist. In diesem Kapitel lernst du die Grundbegriffe: statische vs. dynamische Web-Applikationen, Webserver, HTTP und Web-Services.

## Statische vs. dynamische Web-Applikation

### Statische Web-Applikation

Bei einer **statischen** Web-Applikation liegen die Inhalte **fertig als Dateien** vor (z. B. als HTML-, CSS- und JavaScript-Dateien). Der Server liefert die Datei **unverändert** an den Client aus. Für jeden Aufruf erhält der Client die gleiche Datei.

- Inhalte sind fix in den Dateien gespeichert
- Keine Datenbank, keine Logik auf dem Server nötig
- Schnell und einfach zu hosten
- Beispiel: eine reine Informationsseite über ein Medikament

### Dynamische Web-Applikation

Bei einer **dynamischen** Web-Applikation wird der Inhalt **zur Laufzeit** erzeugt. Der Server führt Logik aus, liest aus einer Datenbank und erzeugt die Antwort (HTML oder JSON) erst bei der Anfrage. Die Inhalte können von Benutzer zu Benutzer und von Aufruf zu Aufruf unterschiedlich sein.

- Inhalte werden zur Laufzeit erzeugt
- Nutzt Datenbanken, Services, Geschäftslogik
- Ermöglicht personalisierte, interaktive Anwendungen
- Beispiel: eine Patientenverwaltung, bei der jeder Patient seine eigenen Daten sieht

| Aspekt | statisch | dynamisch |
|--------|----------|-----------|
| Inhalt | liegt fertig vor | wird zur Laufzeit erzeugt |
| Datenbank | meist keine | meist vorhanden |
| Logik auf dem Server | keine | vorhanden |
| Beispiel | Info-Seite | Patientenverwaltung, Online-Shop |

## Webserver

Ein **Webserver** ist ein Programm, das HTTP-Anfragen von Clients entgegennimmt und beantwortet. Er liefert statische Dateien aus oder reicht Anfragen an einen Anwendungsteil weiter.

Beispiele:
- **Nginx**, **Apache** – klassische Webserver
- **Tomcat**, **Jetty** – Anwendungs- und Webserver, wie sie in Spring Boot eingebaut sind

Spring Boot bringt einen eingebauten Webserver (Tomcat) mit. Sobald du die Anwendung startest, läuft sie auf `http://localhost:8080/` – ohne dass du einen separaten Webserver installieren musst.

## HTTP

Die Kommunikation zwischen Browser und Webserver läuft über das **HTTP**-Protokoll (siehe Kapitel 01.1). Der Browser sendet eine `GET`-Anfrage, der Webserver antwortet mit einer Response (HTML, JSON usw.).

## Web-Applikation

Eine **Web-Applikation** ist eine Anwendung, 
die eine Web-Oberfläche bereitstellt und
über den Browser genutzt wird.


## Web-Service (Web-API)

Ein **Web-Service** (auch **Web-API**) ist eine Schnittstelle, über die Anwendungen (nicht Menschen) Daten austauschen. Web-Services liefern meist **strukturierte Daten** im **JSON**-Format und werden über **REST-Endpoints** angesprochen.

Beispiel: Der Browser (Client) fragt `GET /api/patients` ab und erhält eine Liste von Patienten als JSON.

## Client-seitige vs. Server-seitige Verarbeitung

Eine Web-Applikation kann Logik auf zwei Seiten ausführen:

- **Server-seitig (server-side):** Der Server führt die Logik aus und liefert fertige Seiten oder Daten. 
Beispiel: eine Spring-Boot-Anwendung, 
die eine HTML-Seite mit Hilfe einer Template-Engine rendert.
- **Client-seitig (client-side):** Der Browser führt JavaScript aus, 
verändert die Seite und ruft bei Bedarf Daten vom Server ab. 
Beispiel: eine Seite, die per `fetch` Daten lädt und in einer Tabelle anzeigt.

Die Begriffe **server-side rendering (SSR)** und **client-side rendering (CSR)** werden in Kapitel 02.1 genauer behandelt.

## Zusammenfassung: Was eine Web-Applikation ausmacht

Eine Web-Applikation besteht typischerweise aus:

```
Client (Browser)  <--HTTP-->  Webserver / Anwendung  <-->  Datenbank
[HTML, CSS, JS]               [Spring Boot, Logik]        [MySQL]
```

- **Frontend:** HTML, CSS, JavaScript – läuft im Browser (Client)
- **Backend:** Serverlogik (z. B. Spring Boot, REST-APIs)
- **Datenbank:** dauerhafte Speicherung der Daten
