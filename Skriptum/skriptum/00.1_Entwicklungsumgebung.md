# 00.1 Entwicklungsumgebung (Browser, VS Code, DevTools)

Bevor wir mit der Webentwicklung beginnen, richten wir die Werkzeuge ein, die du für dieses Skriptum brauchst. Anders als beim Java-Skriptum (JDK + IntelliJ) arbeitest du in der Webentwicklung häufig mit leichteren Werkzeugen.

## Der Browser

Der **Browser** ist das wichtigste Werkzeug der Client-Entwicklung. Du nutzt ihn nicht nur zum Ansehen von Seiten, sondern auch zum Testen und Debuggen. Empfohlen werden **Chrome** oder **Firefox**, da sie sehr ausgereifte Entwicklerwerkzeuge mitbringen.

### Developer Tools (DevTools)

Jeder moderne Browser bringt **Developer Tools** mit, die du meist mit `F12` öffnest. Die wichtigsten Bereiche:

| Bereich | Funktion |
|---------|----------|
| **Elements / Inspektor** | HTML-Struktur und CSS live ansehen und verändern |
| **Console** | JavaScript-Konsolenausgaben, Fehlermeldungen |
| **Sources / Debugger** | JavaScript-Code ansehen, Haltepunkte setzen |
| **Network** | Alle HTTP-Anfragen und -Antworten beobachten |
| **Application** | Session Storage, Local Storage, Cookies ansehen |

## Texteditor / IDE

Für HTML, CSS und JavaScript reicht ein schlanker Editor. Empfohlen wird **VS Code** (Visual Studio Code). VS Code bietet:

- Syntax-Highlighting für HTML, CSS und JavaScript
- IntelliSense (Code-Vervollständigung)
- Integriertes Terminal
- Zahlreiche Erweiterungen (Extensions), z. B. **Live Server** (startet einen lokalen Webserver mit automatischem Neuladen)

> Für die Spring-Boot-Teile (Kapitel 07.x) kannst du weiter IntelliJ verwenden – das kennst du bereits aus dem Java-Skriptum.

## Lokaler Webserver

Bereits ab den HTML/Links-Kapiteln ist es sinnvoll, eine Seite nicht nur als Datei vom Dateisystem (`file://`) zu öffnen, sondern über einen **lokalen Webserver** (`http://localhost`). Viele Browserfunktionen (z. B. `fetch`, Storage) funktionieren zuverlässiger über HTTP. Die VS-Code-Erweiterung **Live Server** startet so einen Webserver mit einem Klick.

## Zusammenfassung

### Wichtige Begriffe
- Browser, DevTools (Elements, Console, Sources, Network, Application)
- VS Code, Live Server
- `file://` vs. `http://localhost`

### Das sollst du können
- DevTools öffnen und die wichtigsten Bereiche benennen
- Eine HTML-Seite mit VS Code und Live Server anzeigen
- Die Konsole des Browsers zum Ausgeben von JavaScript-Meldungen verwenden
