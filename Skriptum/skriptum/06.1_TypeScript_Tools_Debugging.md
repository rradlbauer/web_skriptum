# 06.1 TypeScript – Tools, Setup & Debugging

Damit TypeScript in deiner Entwicklungsumgebung funktioniert, brauchst du Tools: **Node.js**, **npm**, den **TypeScript-Compiler** (`tsc`) und ein Build-Tool. Dieses Kapitel zeigt, wie du alles einrichtest und TypeScript **debuggst**.

## Node.js und npm

**Node.js** ist eine Laufzeitumgebung für JavaScript außerhalb des Browsers. **npm** (Node Package Manager) installiert und verwaltet Bibliotheken und Werkzeuge – die Abhängigkeiten eines Projekts stehen in der Datei `package.json`.

### Node.js installieren

1. Lade Node.js von der offiziellen Website herunter (LTS-Version) und installiere es.
2. Prüfe in der Kommandozeile:

```bash
node --version
npm --version
```

## TypeScript installieren

Den TypeScript-Compiler installierst du über npm – entweder **weltweit** (für einfache Tests) oder besser **pro Projekt**:

```bash
# pro Projekt (empfohlen)
npm init -y
npm install --save-dev typescript
```

```bash
# weltweit (für schnelle Versuche)
npm install -g typescript
```

Das Kommando zum Compilieren heißt `tsc` (TypeScript Compiler):

```bash
# einzelne Datei compilieren
npx tsc datei.ts

# automatisch überwachen (watch mode)
npx tsc --watch
```

`datei.js` entsteht neben der TypeScript-Datei.

## tsconfig.json

Für Projekte legst du die Compiler-Einstellungen in der Datei `tsconfig.json` ab. Erzeugen kannst du sie so:

```bash
npx tsc --init
```

Wichtige Optionen:

```json
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "ES2022",
    "strict": true,
    "rootDir": "src",
    "outDir": "dist",
    "sourceMap": true
  },
  "include": ["src"]
}
```

| Option | Bedeutung |
|--------|-----------|
| `target` | in welche JavaScript-Version compiliert wird |
| `module` | Modulsystem (z. B. ES-Module) |
| `strict` | strenge Typprüfung einschalten (empfohlen) |
| `rootDir` | Verzeichnis mit den TypeScript-Dateien |
| `outDir` | Verzeichnis für die generierten JavaScript-Dateien |
| `sourceMap` | erzeugt Source Maps (wichtig fürs Debugging, siehe unten) |

Mit `target`/`rootDir`/`outDir` gilt:

```
src/patient.ts  --tsc-->  dist/patient.js
```

## Build-Tools: Vite

Für **Web-Applikationen** compiliert man nicht nur, sondern braucht einen **Entwicklungs-Server** (wie Live Server, nur für TypeScript/Aktionen). Das modernste Werkzeug ist **Vite**:

- Startet einen lokalen Entwicklungs-Server mit **automatischem Neuladen** (Hot Module Replacement)
- Compiliert TypeScript **automatisch** – du schreibst `.ts`, Vite liefert `.js`
- Bündelt (bundelt) am Ende die Dateien für den Produktiveinsatz

```bash
npm create vite@latest patientenverwaltung -- --template vanilla-ts
cd patientenverwaltung
npm install
npm run dev
```

Der Entwicklungs-Server läuft dann z. B. unter `http://localhost:5173/`. Die SPA-Struktur (eine `index.html` + `src/app.ts`) kennst du bereits aus Kapitel 02.1 bzw. lernst in Kapitel 09.1 kennen.

## Integration in VS Code

VS Code unterstützt TypeScript **von Haus aus**:

| Zweck | Werkzeug in VS Code |
|-------|---------------------|
| IntelliSense (Vervollständigung) | eingebaut, sobald TS-Dateien geöffnet sind |
| Fehlermeldungen | als Wellenlinie im Editor angezeigt |
| Quick Fixes | Vorschläge des Compilers automatisch anwenden |
| Refactoring | Umbenennen, Auslagern von Funktionen |
| Linting & Formatierung | ESLint + Prettier als Erweiterungen |

Nützliche Erweiterungen:

| Erweiterung | Zweck |
|-------------|-------|
| **ESLint** | Code-Qualitätsprüfung (unbenutzte Variablen, fehlerhafte Muster) |
| **Prettier** | einheitliche Formatierung |
| **TypeScript Vue/React** (je nach Framework) | Framework-Unterstützung |

Für die Spring-Boot-Teile (Kapitel 08.x) verwendest du weiterhin **IntelliJ**; TypeScript-Frontend-Code lässt sich dort ebenfalls bearbeiten.

## Debugging von TypeScript

### Warum Source Maps?

Der Browser führt **JavaScript** aus, nicht TypeScript. Damit du im Browser (oder Debugger) den **TypeScript-Originalcode** mit Haltepunkten sehen kannst, brauchst du **Source Maps**: Sie verlinken die generierte JS-Datei mit der TS-Quelldatei.

In `tsconfig.json` aktivierst du `"sourceMap": true` (Vite erzeugt Source Maps standardmäßig). Im Browser erscheint dann im **Sources**-Bereich neben `dist/patient.js` die Datei `src/patient.ts`.

### Debugging in den DevTools

1. Öffne die Seite in Chrome/Firefox und starte die DevTools (`F12`).
2. Wechsle in den Bereich **Sources**.
3. Öffne dort die `.ts`-Datei (über die Source Map).
4. Setze einen **Haltepunkt** (Klick auf die Zeilennummer).
5. Starte die Aktion in der Seite und steige mit den Pausentasten durch die Zeilen.
6. Beobachte Variablenwerte im **Scope**-Bereich und in der **Konsole**.

### Debugging in VS Code

VS Code besitzt einen eingebauten JavaScript/TypeScript-Debugger. Du erstellst eine Startkonfiguration in `.vscode/launch.json`:

```json
{
  "version": "0.2.0",
  "configurations": [
    {
      "type": "chrome",
      "request": "launch",
      "name": "Debug in Chrome",
      "url": "http://localhost:5173",
      "webRoot": "${workspaceFolder}/src"
    }
  ]
}
```

Danach:

1. Vite-Dev-Server starten (`npm run dev`)
2. In VS Code die Konfiguration "Debug in Chrome" starten (`F5`)
3. Haltepunkte direkt in der `.ts`-Quelldatei setzen
4. Mit den Debug-Tasten ausführen, Step over/into, Variable ins Watch-Fenster legen

Auch **Konsolenausgaben** (`console.log`) erscheinen wie gewohnt in der DevTools-Console bzw. im Debug-Fenster.

### Typische Debugging-Abläufe

| Situation | Ansatz |
|-----------|--------|
| Funktion liefert falsches Ergebnis | Haltepunkt in der Funktion, Variablen prüfen |
| Element wird nicht gefunden | Haltepunkt nach DOM-Zugriff, `document.getElementById(...)` prüfen |
| Fehler beim Compilieren | Compiler-Fehlermeldung im Terminal/in VS Code beachten (zuerst TypeScript-Fehler beheben) |

> **Regel:** Erst sorgt der TypeScript-Compiler für typsicheren Code, dann wird zur Laufzeit im Debugger untersucht, *was* passiert.

## Zusammenfassung

### Wichtige Begriffe
- Node.js, npm, `package.json`
- TypeScript-Compiler `tsc`, `tsc --watch`
- `tsconfig.json`: `target`, `strict`, `rootDir`, `outDir`, `sourceMap`
- Build-Tool **Vite** (`npm run dev`)
- VS Code: IntelliSense, ESLint, Prettier
- Debugging: Source Maps, Haltepunkte, DevTools Sources, `launch.json`

### Das sollst du können
- TypeScript mit npm installieren und eine Datei mit `tsc` compilieren
- Eine `tsconfig.json` einrichten und ihre wichtigsten Optionen erklären
- Ein Vite-Projekt mit TypeScript anlegen und starten
- TypeScript im Editor und im Browser über Source Maps debuggen
