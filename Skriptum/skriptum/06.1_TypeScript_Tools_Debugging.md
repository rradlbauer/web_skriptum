# 06.1 TypeScript – Tools, Setup & Debugging

Damit TypeScript in deiner Entwicklungsumgebung funktioniert, brauchst du Tools: **Node.js**, **npm**, den **TypeScript-Compiler** (`tsc`) und ein Build-Tool. Dieses Kapitel zeigt, wie du alles einrichtest und TypeScript **debuggst**.

## Node.js und npm

**Node.js** ist eine Laufzeitumgebung für JavaScript außerhalb des Browsers. **npm** (Node Package Manager) installiert und verwaltet Bibliotheken und Werkzeuge – die Abhängigkeiten eines Projekts stehen in der Datei `package.json`.

### Node.js installieren

1. Lade Node.js von der offiziellen Website herunter (LTS-Version)   
alternativ kannst du es auch mit Winget installieren: 
tippe in einer Kommandozeile diesen Befehl ein:  
`winget install -e --id OpenJS.NodeJS.LTS`
2. Prüfe in der Kommandozeile:

```bash
node --version
npm --version
```

## TypeScript installieren

Die folgenden Schritte führst du am besten mit VisualStudio Code
(VS-Code) aus. Lege zuerst ein leeres Verzeichnis für dein 
Projekt an und öffne es mit SV-Code (File - Open Folder).  
Öffne dann ein neues Terminal und gib die weiteren Befehle
hier ein.

Im Folgenden werden die Befehle `npm` und `npx` verwendet.
`npm` installiert Pakete, `npx` führt sie aus.
In der Powershell musst du manchmal statt `npm`
den Befehl `npm.cmd` und statt `npx` den Befehl `npx.cmd` verwenden.

Den TypeScript-Compiler installierst du über `npm`:


```bash
# pro Projekt (empfohlen)
npm init -y
npm install --save-dev typescript
```

`npm init -y` erzeugt eine `package.json`, 
in der die Abhängigkeiten stehen.  
`npm install` lädt die Pakete herunter 
und legt sie im Unterverzeichnis `node_modules` ab.
`--save-dev` bedeutet, dass TypeScript nur für die 
Entwicklung gebraucht wird.

Du könnt TypeScript auch **weltweit** installieren, 
dann steht der Compiler `tsc` in allen Projekten zur Verfügung.
Das ist aber nicht unbedingt empfehlenswert, 
weil verschiedene Projekte unterschiedliche TypeScript-Versionen 
benötigen könnten. Falls du es trotzdem ausprobieren willst, 
kannst du das so tun:


```bash
# weltweit (für schnelle Versuche)
npm install -g typescript
```

Als nächstes kannst du die Version prüfen:

```bash
npx tsc --version
```

`tsc` (TypeScript Compiler) ist der Befehl, 
der TypeScript-Dateien in JavaScript übersetzt.


## tsconfig.json

Für Projekte legst du die Compiler-Einstellungen in der Datei `tsconfig.json` ab. Erzeugen kannst du sie so:

```bash
npx tsc --init
```

Wichtige Optionen:

```json
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "ES2022",
    "strict": true,
    "rootDir": "src",
    "outDir": "dist",
    "sourceMap": true
  },
  "include": ["src"]
}
```

Wichtig: `target` und `module` musst du anpassen, 
damit es im Browser funktioniert.

Hier die wichtigsten Optionen im Überblick:


| Option | Bedeutung |
|--------|-----------|
| `target` | in welche JavaScript-Version compiliert wird |
| `module` | Modulsystem (z. B. ES-Module) |
| `strict` | strenge Typprüfung einschalten (empfohlen) |
| `rootDir` | Verzeichnis mit den TypeScript-Dateien |
| `outDir` | Verzeichnis für die generierten JavaScript-Dateien |
| `sourceMap` | erzeugt Source Maps (wichtig fürs Debugging, siehe unten) |

Mit `target`/`rootDir`/`outDir` gilt:

```
src/patient.ts  --tsc-->  dist/patient.js
```

## Compilieren und Watch-Modus

```bash
# einmalig compilieren
npx tsc 
# automatisch bei Änderungen compilieren
npx tsc --watch
```

Wenn du im Terminal `npx tsc --watch` laufen lässt, 
wird bei jeder Änderung an einer `.ts`-Datei automatisch 
die entsprechende `.js`-Datei erzeugt.

Daher ist die Entwicklung am einfachsten, 
wenn du den Compiler im **Watch-Modus** laufen lässt und 
deine HTML-Datei mit dem Live-Server öffnest.

## Script in HTML einbinden

```html
<script type="module" src="./dist/patient.js"></script>
```

Wichtig ist, dass du das JavaScript-File einbindest,
und nicht die TypeScript-Datei. Außerdem musst du `type="module"`
verwenden, damit die ES-Module korrekt geladen werden.




## Debugging von TypeScript

### Warum Source Maps?

Der Browser führt **JavaScript** aus, nicht TypeScript. Damit du im Browser (oder Debugger) den **TypeScript-Originalcode** mit Haltepunkten sehen kannst, brauchst du **Source Maps**: Sie verlinken die generierte JS-Datei mit der TS-Quelldatei.

In `tsconfig.json` aktivierst du `"sourceMap": true` (Vite erzeugt Source Maps standardmäßig). Im Browser erscheint dann im **Sources**-Bereich neben `dist/patient.js` die Datei `src/patient.ts`.

### Debugging in den DevTools

1. Öffne die Seite in Chrome/Firefox und starte die DevTools (`F12`).
2. Wechsle in den Bereich **Sources**.
3. Öffne dort die `.ts`-Datei (über die Source Map).
4. Setze einen **Haltepunkt** (Klick auf die Zeilennummer).
5. Starte die Aktion in der Seite und steige mit den Pausentasten durch die Zeilen.
6. Beobachte Variablenwerte im **Scope**-Bereich und in der **Konsole**.

### Debugging in VS Code

VS Code besitzt einen eingebauten JavaScript/TypeScript-Debugger. Du erstellst eine Startkonfiguration in `.vscode/launch.json`:

```json
{
  "version": "0.2.0",
  "configurations": [
    {
      "type": "chrome",
      "request": "launch",
      "name": "Debug in Chrome",
      "url": "http://localhost:5500",
      "webRoot": "${workspaceFolder}/dist"prompt("your age: ")
    }
  ]
}
```

Danach:

1. Live Server starten
2. In VS Code die Konfiguration "Debug in Chrome" starten (`F5`)
3. Haltepunkte direkt in der `.ts`-Quelldatei setzen
4. Mit den Debug-Tasten ausführen, Step over/into, Variable ins Watch-Fenster legen

Auch **Konsolenausgaben** (`console.log`) erscheinen wie gewohnt in der DevTools-Console bzw. im Debug-Fenster.

## Zusammenfassung

### Wichtige Begriffe
- Node.js, npm, `package.json`
- TypeScript-Compiler `tsc`, `tsc --watch`
- `tsconfig.json`: `target`, `strict`, `rootDir`, `outDir`, `sourceMap`
- Debugging: Source Maps, Haltepunkte, DevTools Sources, `launch.json`

### Das sollst du können
- TypeScript mit npm installieren und eine Datei mit `tsc` compilieren
- Eine `tsconfig.json` einrichten und ihre wichtigsten Optionen erklären
- TypeScript im Editor und im Browser über Source Maps debuggen
